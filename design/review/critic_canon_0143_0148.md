не «дорабатываю»: читаю дерево, меряю кодом, пишу дыры. Решать — директору игры.

**Что проверял:** `docs/decisions/0143…0148` против кода `sim/src/`, каталогов `design/catalogs/`,
документов `docs/00`, `docs/03`, `docs/09*` и `AGENTS.md`.

Все числа ниже — на этом рабочем дереве; на чистом HEAD они не воспроизводятся.

## Находки по приоритетам

### Приоритет 1. Вечный двигатель и дюп — 3 находки

Материя из ничего **не обнаружена**. Проверено и сходится:

- `Ledger.transfer` — единственный путь движения; `_charge` бросает при нехватке
  (`sim/src/hillcourt/ledger.py:41`). Прогон `v0_shire` 36 мес, seed 1729: `matter_delta 0.000000`,
  прямым замером `world.ledger.delta(world.total_matter())` = `1.46e-11` (шум float).
- Продажа зерна идёт **только** переводом: `_settle_sale` требует `barn >= amount`
  (`economy/exchange.py:596`) и переводит зерно из амбара в сток двора (`:613`).
- **Потолок закупки не обходится.** Оба канала пишут в один счётчик
  (`exchange.py:665` и `:791` → `_count_purchase` `:129-139`), счётчик штампуется месяцем
  (`:139`), `purchase_allowance_left` (`:124-126`) режет обе покупки (`:655-658`, `:745`).
- **Прилавок не двоит зерно.** Это не второй сток, а кап: зерно остаётся в `manor:<id>`
  (`list_manor_grain` `:670-692` только пишет число в `world.stats`), а реальное списание делает
  `_settle_sale`. Продать одно и то же зерно дважды за месяц нельзя.
- **Порядок «после посева» — правда.** `manor_month` (`economy/manor.py:569-630`):
  `_gafol` 611 → `_sow_demesne` 612 → `_work_demesne` 613 → `_board` 614 → `_offer_surplus` 615.
  Найм раньше (606-609) — тоже до прилавка. ADR 0148 п. 2 подтверждён.

**1.1. Находка (существенная). Потолок закупки — не единственный и не главный поток зерна из
амбара барона, а закон 0144 называет его главным.**
Из того же стока манора зерно уходит дворам ещё двумя путями, которые потолок не трогают:
- паёк `_board` (`economy/manor.py:275-307`), ставка `board_grain_per_adult` × `monthly_food_need` × буфер;
- жалованье найму `_hire` (`economy/manor.py:344-357`), `wage_grain_per_day = 0.12`
  (`design/catalogs/manor.yml:51`) из **того же** амбара, `landless`-двору, без потолка
  закупки. ADR 0144 п. 2 называет потолок закупки тем, что «держит голод»; измерять это
   свойство на одном канале при трёх открытых — некорректно. `docs/09_economy.md:298-300`
   об этом молчит.

**1.2. Находка (существенная). Причинная связь 0144 «потолок держит голод» сегодня пуста:
потолок не связывает ничего, потому что рынок не работает вовсе.**
Замер, `v0_shire`, 36 мес, seed 1729, скрипт сценария применён (через `runner.run`):
```
manor_grain_bought_* ненулевых: 0
manor_grain_sold_market: нет     manor_grain_sold_direct: нет
manor_offer_grain_*: {manor_hill: 2.25, manor_hh_retinue_p1: 1.41, manor_hh_03_p1: 10.35}
живых дворов 27, с недобором 9, из них с серебром > 0 — 0
серебра во всём мире: 15.0
```
Механика мёртвая не из-за потолка. `_settle_sale` — «всё или ничего» (`exchange.py:605`):
у всех девяти голодных дворов нет ни серебра, ни товара с каталожной ценой, сделка не
закрывается. ВторойContributor: `apply_relief` идёт **раньше** прилавка в `phase_exchange`
(`engine/tick.py:409-412`) и закрывает недобор просящим. Значит инвариант «голод остаётся
возможным» (ADR 0124) держится **не тем, чем ADR 0144 его обосновывает**, а отсутствием
серебра и гейтом `request_relief`. Закон не врёт числом, но врёт причинностью.

**1.3. Находка (существенная). Потолок 0144 обходим ценой, а не количеством.**
`sell_manor_grain(..., price_per_unit: float | None = None)` (`exchange.py:617-624`,
`:652`) принимает произвольную цену за единицу. Гейт один: `price <= EPSILON → 0.0` (`:653`).
Цена `1e-9` проходит (EPSILON = `1e-9`), и двор выкупает весь амбар почти даром — в пределах
потолка по количеству, но с обходом закона 0144 п. 1 «цена зерна — число каталога». Сейчас
безвредно: вызывающих нет (см. 2.2). Но ADR 0144 объявляет константу удалённой и не замечает,
что **цену по-прежнему можно задать извне**. Это же — нестыковка с ADR 0139 п. 2 («барон сам
назначает цену») против ADR 0139 п. 6 и ADR 0144 п. 1 («цена — каталог»). Ни один из шести
ADR этого не разбирает.

### Приоритет 2. Всеведение и И-3 — 2 находки

Контекст: в дереве **нет ни одного отчёта** ни о продаже зерна, ни о подаче, ни о зарплате.
`grep -rn "manor_grain|sell_grain|амбар" sim/src/hillcourt/news/ sim/src/hillcourt/info/` даёт
только два попадания, и оба — докстринги про обоз (`info/briefing.py:155,361`).

**2.1. Находка (существенная). ADR 0148 вводит видимый игроку результат и не рождает для него
`Report` — а канон через три документа требует обратного.**
`offer_manor_surplus` + `sell_listed_grain` двигают зерно из амбара барона в стоки дворов —
это ровно тот класс события, который ADR 0150 п. 3 (написан **после** 0148) объявляет законом:
«Видимый результат — **вести, а не истина с клетки**… рождает `Report` с `subject_kind="tile"`,
датой и фактом `roadwork_completed`». Продажа не рождает ничего: только `world.bump`
(`exchange.py:666`, `:795`). Тот же промах — у `apply_relief` (`:217`) и найма.
Смягчающее: 0148 написан раньше 0150, винить его за нарушение нормы, которой тогда ещё не
было, нельзя. Но **разрыв есть, и закрывать его нечем**: И-3 не имеет ни одного механизма
контроля на экономических событиях. Для сравнения, угрозы контролируются жёстко: `phase_hazard`
откатывает рождение, если вести нет (`engine/tick.py:599-609`).
Оговорка к формулировке задачи: в самом ADR 0148 **нет ни слова** о постройках и дорогах —
это тема ADR 0150. Проверял по существу: видимые последствия 0148 (амбар пустеет, зерно
переезжает) вести не несут.

**2.2. Находка (критическая, см. также 3.1). Канал №1 продажи по-прежнему мёртв.**
`grep -rn "sell_manor_grain|list_manor_grain" sim/src/` даёт **только определения** (`:617`,
`:670`) и упоминания в докстрингах (`:8-9`). Ни одного вызова ни из тика, ни из движка, ни из
runner. Живой ровно один путь: `manor.py:566 → offer_manor_surplus → tick.py:412
sell_listed_grain`. То есть ADR 0148 п. 4 («**Действуют все механизмы ADR 0139 и 0144 сразу:**
два канала — прямая продажа и выставка в деревне») **не соответствует дереву**: работает один
канал из двух. Это в точности тот дефект, который ADR 0148 сам называет «закон выглядел
исполненным, потому что его тесты зелёные, а игра его никогда не звала» — на один канал глубже.

**3.9. `0145:32` — «Валюта и единица берутся из `obligations.yml`

расхождения онтологии с каталогом.

**3.10. `0145:32` — «серебро — счётчик `Household`/книги» — серебра в `Household` нет.**

**3.11. `0146:32` — «`docs/07` прямо требует, чтобы пресет был различим по осям» — выдумано.**
В `docs/07_legal.md` такого требования нет: `:27` — «Пресет — ярлык из `legal_statuses.yml`,
а не отдельный класс в коде. Ровно 8 пресетов», дальше таблица и список прав (`:40`).
Более того, канон сам содержит пресет, не различимый по осям: `holder` и `thegn`
