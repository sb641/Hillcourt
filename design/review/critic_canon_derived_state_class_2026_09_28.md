### 2.1 `world.script` — очередь приказов И реестр дворов одновременно

- **Видно игроку:** полностью. И это мина порядка загрузки: состав приезжающего

### 2.2 `load_scenario` возвращает мир, в котором нельзя играть
`design/scenarios/start_stand.yml:97-105` (весь блок `script:`), `runner.py:315`

- **Что вычисляется один раз:** в `start_stand.yml` **нет ключа `regime:` ни разу**.
  Режимы шести пашен и все пять наделов появляются только из `script:` на 1-м месяце.
- **Что игрок меняет:** ничего — это происходит до первого хода.
- **Что не происходит:** `load_scenario('start_stand')` + `run_month` × 24 **воспроизводит
  сегодняшнюю поломку до сантиметра**:
  ```
  growth_tile_ids == ('t_00_00','t_01_00','t_03_00','t_03_01')   ← РОВНО старое значение
  шесть пашен: 8.00 зерна, заморожены
  t_01_00:  8699.50 зерна создано правилом grow_grain за 120 месяцев
  все 11 прочих клеток: 0.00
  harvest_grain: 0 вызовов на ВСЕЙ карте
  за 24 месяца: 5 рецептов, все на t_03_01
  ```
  С отыгранным скриптом — 9 рецептов и жатва на всех шести полях. Правка настоящая;
  **но ловушка измерения осталась**, и именно через неё поломку и замерили в первый раз.
- **Видно игроку:** это и есть репорт. Достижимо из трёх строк кода.
- Повтор скрипта живёт в **трёх** местах: `runner.run` (единственный публичный путь,
  но он не даёт смотреть мир помесячно) и два приватных тест-хелпера —
  `test_start_stand.py:61`, `test_rent_base_window.py:47`. **Публичного
  «загрузить и отыграть со своим скриптом» API нет.**

### 2.3 `Person.personal_status` — одно поле, два разных смысла
`ontology.py:78` (дефолт `"free"`), `scenario.py:905` (пишет в `Household`, не в `Person`),

- **Видно игроку:** сейчас не видно — оба читателя (`legal/calendar.py:104`,

## 4. Вердикт

**Это системный класс, а не один баг.** Девять находок из девяти — разные подсистемы
(реестр дворов, загрузчик сценария, онтология людей, правовой статус, календарь
приказов, книга манора, миграция), и у шести из них **общий признак**: величина
не выводится на чтении, а копируется в поле, и копию обновляет меньше писателей,
чем пишет саму величину. Механизм один — «у факта несколько домов, и приказ игрока
обновляет не все». Сегодняшняя поломка роста — частный случай; 2.1–2.2 показывают,
что она же воспроизводится ещё и через порядок загрузки.
