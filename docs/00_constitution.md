# 00. Конституция

## Назначение

Инварианты проекта. Задача, требующая нарушить инвариант, останавливается и уходит в ADR.
Ниже — что именно проверяется и чем.

## Правила

### И-1. Материя не берётся из ничего
Ни один тик не создаёт и не уничтожает вещество. Любое количество — перевод между контейнерами
(двор, склад, тайл, обоз, счёт-сток) или внешний поток, у которого есть **правило появления**.
Все товары соизмеримы в одной массовой единице, поэтому баланс
`sum(inputs)+sum(draws_standing) == sum(outputs)+sum(loss)` — это настоящий массовый баланс, а
`Ledger.emit` требует явно объявленный набор товаров рецепта и не позволяет подменить одно
вещество другим.
· Проверка: `sim/tests/test_matter_conservation.py`, в т.ч. `test_emit_refuses_undeclared_good`.

### И-2. Право, а не микроменеджмент
Действие игрока меняет право, повинность или посылку людей (`Tenure`, `Obligation`, `Pack`),
а не приказывает конкретному человеку рубить дерево.
· Проверка: список `PlayerAction` в `docs/03_ontology.md`; в коде нет функций вида `chop_wood(person)`.

### И-3. Известие ≠ мир
Игрок не читает `Tile`/`Household` напрямую. Его знание — это список `Report` с датой, источником
и уверенностью. Истина симуляции игроку недоступна.
· Проверка: представление игрока собирается только из `Report` (критерий — `docs/05_information.md`).

### И-4. LOD: месяц — основной тик
Подробно считается месяц. Дневной контур включается только для сущностей в пути (`Pack`)
или в инциденте (`Hazard`). Симуляции всех людей по всем клеткам каждый день нет.
· Проверка: дневной контур не содержит цикла по всем `Person` (`docs/06_lod.md`).

### И-5. Симуляция не знает рендера
`sim/` не импортирует Godot и графику. Рендер не считает ренту и не двигает материю.
· Проверка: в `sim/src/` нет импортов `godot*`, `pygame`, `PIL`.

### И-6. Детерминизм
Один `seed` и один сценарий дают один результат. Случайность идёт через именованные потоки RNG.
· Проверка: `sim/tests/test_tick_runs.py` (повторный прогон совпадает).

### И-7. Объект материи обязан иметь место
У каждого товара есть `storage`, у каждого результата — `recipe` или `spawn_rule`.
· Проверка: `sim/tests/test_catalog_rules.py`.

### И-8. Лор без онтологии — брак
Любое имя, орден, империя, реликвия в документе обязаны иметь сущность в `docs/03_ontology.md`
или запись в каталоге. Иначе фраза удаляется. Реликвии в v0 — редкий объект без лута и `+ATK`.
· Проверка: ручной критерий Critic — каждое имя существительное-имя собственное трассируется в онтологию.

### И-9. Документ без проверки — брак
У каждого документа есть блок **Проверка** с командой, тестом или однозначным ручным критерием.
· Проверка: ревизия `docs/` по разделу 5.1 `AGENTS.md`.

### И-10. Запрещённые конструкции
Нет классов `Knight`/`Explorer`, нет вызова LLM в тике двора, нет pathfinding всех людей.
· Проверка: grep по `sim/src/` на `class Knight`, `class Explorer`, импорты LLM-клиентов.

## Проверка

```bash
bash sim/run_tests.sh
```

Плюс ручной аудит: каждый документ `docs/00`–`docs/06` содержит блок «Проверка»;
каждое имя собственное из документов есть в `docs/03_ontology.md` или в `design/catalogs/`.
