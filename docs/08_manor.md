# 08. Манор

> Вводная и карта срезов по праву и земле — `docs/09_law_and_land.md`; право — `docs/07_legal.md`.

## Назначение

Манор — **книга земли** держателя: какие клетки и дворы ему принадлежат, кто держатель,
какой долг уходит вверх. Тэн — не класс юнита, а **вложенный манор** с другим долгом вверх.
Игрок в v0 владеет ровно одним корневым манором. Модуль-владелец — `sim/src/hillcourt/engine/manor.py`
(роль Manor Implementer).

## Правила

### Модель (`ontology.Manor`)
`id`, `holder_person_id`, `stock_id` (обязателен: корень — `settlement:hill_court`,
тэн — `manor:<id>`), `tile_ids[]` (+ `tile_regimes: dict[tile_id, regime]`),
`household_ids[]`, `parent_manor_id` (у игрока `null`), `upward_bundle`
(игрок: `crown_stub`/`none`; тэн: `thegn_service`),
`demesne_labor_demand_this_month`, `demesne_labor_filled`, `grant_ids[]`, `mustered`,
`prior_preset`, служба — `service_kits_required`, `service_men_required`, `service_kits_held`,
`service_men_held`, `service_met`, `service_gap`, `bad_service_months`, `iron_requested`;
место стола — `seat_tile_id` (клетка зала, только корень), `seat_tiles`, `eye_range_tiles`,
`peace_range_tiles`. `guard_ring` тэна (книга + соседи) вычисляется и не хранится.

Реестр — `World.manors` + `World.player_manor_id`; действия игрока — `World.player_actions`.
Двор всегда кормится из одной книги: `Household.manor_id` (у соляных держателей — `null`,
они равные, вне тяглой книги).

### Корень и вложенность
- Корневой манор `manor_hill` создаётся сценарием: его клетки — вся земля баронии
  (соляная деревня остаётся **клетками того же манора**, не вторым фьефом), тяглые дворы —
  все, кроме соляных держателей (те равные, не тяглые).
- `grant_thegn(person, tiles, households)`: не больше `grants` раз (сценарий
  `player.thegn_grant_limit.grants`; по умолчанию 1, в `v0_shire` — 2), ≤ лимита сценария
  (по умолчанию ≤3 клетки и ≤3 двора, жёсткий потолок `THEGN_MAX_*`). Создаёт вложенный манор
  с `upward_bundle: thegn_service`, `depth = 1`, **амбар `manor:<id>`** и переводит дворы
  на `manor_id` тэна. Требует ≥1 доменной клетки среди пожалованных. При исчерпанном лимите
  пожалование отклоняется (`grant_thegn_rejected reason=grants_limit`). Двор самого держателя
  входит в книгу тэна (сверх лимита тяглых). Вложенный тэн **дальше не жалует**.
- `revoke_thegn(manor_id)` — простой отзыв: земля, дворы и **амбар** возвращаются в корень
  (слияние через `Ledger.transfer`), без войны. Заглушка «не в v0» не понадобилась.
  Бывший держатель не удаляется и не возвращается к старому пресету: он остаётся живым
  **свободным без земли** (`free_landless`).

### Служба тэна: земля содержит службу (ADR 0021)
Тэн — военный профессионал, а не крестьянин с титулом: земля выдана под службу, служба
измеряется объектами книги, а не статом.
- **Норма.** `grant_thegn` пишет `service_kits_required = 1 (сам) + тяглые дворы` и
  `service_men_required = взрослые двора держателя`.
- **Комплект.** `mustered` требует `war_kit ≥ 1` **на дворе держателя** (`holder_kits`);
  `service_met` сверяет норму с `fief_kits` (амбар + двор держателя), явку `men_held` и
  сытость, т.е. комплект в амбаре тоже зачитывается (`engine/manor.py:596-630`). Комплект
  собирается из инертной крицы (`smith_kit`: `iron_bloom 1.0 → war_kit 1.0`, труд 10) в
  амбар своего манора, при нехватке — `thegn_iron_request`. Никакого `+ATK`.
- **Кольцо.** `guard_ring` = клетки книги + непосредственные соседи, вычисляется. Это
  радиус вылазки тэна; он **не** равен глазу холма (`eye_range_tiles` корня, ADR 0023).
- **Вылазка.** `thegn_month` в конце `phase_manor`: голод — ни сборки, ни вылазки; сытый с
  закрытым голодом собирает ≤1 комплекта/мес; угроза на кольце (узнанная слухом) — вылазка
  той же `send_party`, ≤1/мес, шанс 0.5 (`rng_world`), за пределы кольца тэн не посылается.
- **Отзыв.** Сигнал `revoke_due` (`bad_service_months ≥ 6` + развал держания) — не
  автособытие: отзывает корень. `revoke_thegn` возвращает землю/дворы/**амбар** и делает
  бывшего держателя `free_landless`; слот не освобождается (`grant_ids` — история).
- **Честные границы v0.** `iron_bloom` землёй **не возобновляется** (появления правилом
  нет): рецепт `smelt_iron_bloom` есть в каталоге, прежней проводки его к действию не
  было — проводка засвидетельствована ADR 0037 (очередь `idle_repair`, гейт сытости).
  Фьеф живёт выплавкой из своего железа, обменом и выдачей корня — «земля кормит
  службу» верно для стола, но не для военного сырья (GAP, ADR 0021). `mustered` — флаг (`war_kit ≥ 1`), боевого движка и
  гарнизона нет; вылазка — существующая `send_party`, не армия. Норма `1 + тяглые` замирает
  при `grant_thegn` и не пересчитывается, если тяглые ушли; `revoke_due` шлётся ровно на
  `bad_service_months == 6`.

### Действия игрока (месячные, в лог)
| действие | что делает |
|---|---|
| `set_tile_regime(tile, regime)` | меняет режим/надел клетки |
| `grant_tenement(household, tiles)` | режим надела, `Right`, запись в книгу |
| `call_boon(month)` | помогает (bene) только в месяц `boon_allowed` |
| `ease_week_work(month, delta)` | урезает барщину пика (не больше долга) |
| `grant_tool(household, good, amount)` | перевод железа (`iron_share`/`iron`/`iron_bloom`, ADR 0021) корень → двор |
| `grant_thegn(person, tiles, households)` | вложенный манор (лимит `grants` из сценария) |
| `revoke_thegn(manor_id)` | возврат земли в корень |

Каждое действие пишет запись в `World.player_actions` (`date`, `action`, поля).

### Хозяйство тэна: контракт амбара (ADR 0010, 0011)
Контракт **зафиксирован**: право и принадлежность амбара — за Manor Implementer, перевод
сбора/кормления на амбар — за Economist. «Сгорание дней = фича v0» снято: это был долг,
а не модель. Долг закрыт (перевод — ADR 0011).

- **Амбар обязателен.** `Manor.stock_id` не пуст: корень — `settlement:hill_court`,
  тэн — `manor:<id>`, заводится в `grant_thegn` (лениво не позже). `grant_thegn` без
  создания амбара запрещён; если id занят не манором — отказ.
- **Одна книга на двор.** `Household.manor_id` — единственный адрес стола; после
  `grant_thegn` двор числится у тэна и не проходит `_is_root_household`. Оставить двор
  без книги нельзя.
- **Домен обязателен.** Режимы клеток при grant не меняются, но среди пожалованных
  должна быть ≥1 `regime:demesne`, иначе `grant_thegn` отклоняется.
- **Revoke.** Земля, дворы и **амбар** тэна сливаются в родителя через `Ledger.transfer`;
  мёртвый `manor:<id>` снимается. Зерно не двоится, не сгорает, не остаётся на мёртвом id.
- **Голод тэна.** `mustered = держатель жив и не голоден ПО СВОЕМУ стоку/двору`
  (`thegn_hungry`), не по замку холма. Обновляется в `phase_record`.
- **Паёк по нужде всего двора.** `_board` (`economy/manor.py:_board`) кормит двор из амбара
  ЕГО книги (`manor_of_household` → `manor_stock`): корень — из `settlement:hill_court`, тэн —
  из `manor:<id>`. Нужда считается `monthly_food_need` (взрослый 1.0, ребёнок 0.7 — рты целиком,
  а не только взрослые) × буфер против порчи; чужой амбар двор не кормит. Держатель манора при
  этом не уходит (J1/I3, `legal/regimes.py:can_leave`), а `mustered` читает его собственный
  амбар, не замок холма.
- **Помочи.** `call_boon`/`ease_week_work` в v0 — только корень; тэн помочи не кричит.
- **Статус перевода (Economist).** Перевод на `manor.stock_id` **закрыт** (ADR 0011):
  паёк (`_board`), гэфоль, посев и урожай тэна идут через амбар своего манора. После
  `grant_thegn` держательский двор входит в книгу тэна (сверх лимита тяглых), `mustered`
  читает его амбар. Трудодни не пересчитываются — только принадлежность амбара.

### Что считает экономист (`economy/manor.py`)
- Трудодни двора идут в пул **того манора, в чьей книге он числится**
  (`Manor.demesne_labor_filled`); после `grant_thegn` те же дни видны у тэна и исчезают из корня.
- Спрос домена (`demesne_labor_demand_this_month`) считается по доменным клеткам корня;
  урожай домена идёт в амбар того манора, чей это домен (закрыто, ADR 0011).
- `thegn_service`: флаг `mustered`; боевого движка нет.

### Защита книги (после Critic)
- Соляная деревня не может стать фьефом: `grant_thegn` отвергает соляную клетку, соляной двор
  и соляного держателя.
- Пожалование атомарно: дубль клетки/двора, пустой список, превышение лимита, отсутствие
  доменной клетки или занятый амбар — отказ до правок, книга не теряет землю.
- Жёсткий потолок ≤3 клетки и ≤3 двора (`THEGN_MAX_*`), даже если сценарий задаст больше.
- `grant_tenement` не может взять клетку из чужой (тэновой) книги; `set_tile_regime` не правит
  книгу тэна.
- `revoke_thegn` возвращает землю, дворы и амбар ровно один раз; бывший держатель остаётся
  живым **свободным без земли** (`free_landless`), старый пресет не откатывается.
- Пожалований не больше `grants` из сценария (по умолчанию 1; в `v0_shire` — 2); отзыв слот не
  освобождает (`grant_ids` — история).
- `call_boon` действует: в месяц `boon_allowed` помогает взять дни и без недобора.
- `ease_week_work` ограничен долгом месяца и живёт только свой год-месяц; двора тэна не касается.
- Годовой cap помочи сбрасывается при смене года (`boon_used_year`).

## Проверка

```bash
bash sim/run_tests.sh
PYTHONPATH=sim/src python3 -m unittest discover -s sim/tests -p 'test_manor_entity.py' -v
```

Критерий: `test_manor_entity.py` (21 тест) зелёный — без пожалования дни виллана в корне;
после пожалования те же дни у тэна и не в корне, у тэна есть амбар `manor:<id>` и домен,
`household.manor_id` переведён; grant без амбара и без доменной клетки отклонён; материя не
дублируется; tied не уходит; при лимите 1 второе пожалование отклонено (`grants_limit`); лимит
сценария соблюдён (`grants: 2` в `v0_shire` — два тэна depth 1, третий отклонён); соль не
фьеф; дубль не теряет землю; `revoke` возвращает землю, дворы и амбар ровно один раз
(дельта зерна 0) и оставляет бывшего держателя `free_landless`; `mustered` — по своему стоку,
не по замку холма, и требует `war_kit ≥ 1`;
`call_boon`/`ease_week_work` действуют; зубец августа жив; приёмка 36 месяцев с `grant_thegn`
на месяце 6 — корневая барщина в жатву меньше baseline, в логе `mustered` тэна, дельта
материи 0.
