# 09. Экономика (обзор)

## Назначение

Единая точка входа в экономику v0: инварианты, единицы, поток месяца, кто чем
кормится, и таблица «правило → где задано → чем проверяется». Это **обзор со
ссылками**, а не второй источник истины: числа живут в каталогах, сущности — в
`docs/03`, порядок фаз — в `docs/04`, право — в `docs/07`/`docs/08`.

Владелец: Economist. Кто МОЖЕТ и ЧТО ДОЛЖЕН — Legal; здесь — чем это кормится.

## Правила

### 1. Инварианты (не нарушаются)

- **И-1, материя не из ничего.** Любое количество — `Ledger.transfer` между
  стоками или `external_in` по правилу появления с `rule_id`. `Ledger.emit`
  разрешён только для товаров рецепта. Проверка: `test_matter_conservation`.
- **И-7, объект обязан иметь место.** У товара есть `storage`; у результата —
  `recipe` или `spawn_rule`. Проверка: `test_catalog_rules`.
- **И-6, детерминизм.** Случайность — через `rng_economy/world/news/hazard`;
  порядок фаз и сущностей фиксирован. Проверка: `test_tick_runs`.

### 2. Единицы (полностью — `design/catalogs/README.md`)

| Величина | Обозначение | Смысл |
|---|---|---|
| масса | `unit` | 1 мешок зерна; взрослый съедает ~1 unit/мес |
| питательность | `nutrition` | зерно 1.0, мука 1.2, мясо 1.5 |
| труд | `labor_days` | 1 трудодень = день взрослого; взрослый = 20/мес |
| надел | `tile_plot` | 1 полевая клетка = виргата (30 акров); гайда = 4; коттер = 0.5 |
| воз | `Pack` | обоз — реальный `Pack` с грузом, фуражом, износом телеги, риском пути и гибелью (A1/H) |
| доля/риск | `0..1` | безразмерно |

### 3. Поток месяца (20 фаз, `docs/04_tick.md`)

`season → growth → manor → hay → roadworks → cook_meal → labor → spoil → consume → demography → obligations → exchange → hazard → migrate → caravan → travel → day → decide → inform → record`

| фаза | что делает с материей |
|---|---|
| `phase_growth` | природа: стоячая материя по `spawn_rules` (`external_in`, потолок `cap_per_tile`) |
| `phase_manor` | **труд**: вернуть двору месяц труда → барщина/рабы в пул СВОЕГО манора → паёк из амбара своей книги (`manor:<id>`, корень — замок) по `monthly_food_need` двора → найм → гэфоль и посев → урожай домена в амбар своего манора (не больше спроса) |
| `phase_hay` | косьба сена дворами с тяглом из рук после барщины, до стройки и поля (сено первое; единственная, ADR 0050) |
| `phase_roadworks` | остаток рук после барщины и косьбы (≤40 трудодней/мес на проект, ADR 0067) → проект дороги/брода/моста; дни клетки и материалы ADR 0039 не меняются; материал `log` списан при `start_work` в `sink:waste`; без рук нет прогресса |
| `phase_cook_meal` | смешанный приём пищи из зерна/муки и добавок (`roots`, `greens`, `mushrooms`, `berries`, молоко, яйца, сыр); 2 трудодня, 8 % отходов, блюдо не создаётся как `Good` |
| `phase_labor` | двор работает на **своём наделе** (`feeds_household`) после собственного хозяйства; домен сюда не входит |
| `phase_spoil` | порча в `sink:waste` |
| `phase_consume` | вся корзина съедобных `Good` из `Stock` → `sink:eaten` по `edible_order` (скоропортящееся первым, зерно последним); зимнее топливо и корм скота; нехватка → `hunger_days` |
| `phase_demography` | сытый двор растит семью: старение, недоросли в тягло, роды от излишка (люди — не материя) |
| `phase_obligations` | натуральная рента (`transfer` двор → замок) и запись барщины |
| `phase_exchange` | подмога, тайники, соседский торг (свои пары, затем чужие пары кластера с ценой носителя) — только `transfer` |
| `phase_hazard` | волчья кража зерна; риск пути |
| `phase_migrate` | уход двора на соседнюю клетку, если `can_leave`; держатель ЛЮБОГО манора (корень и тэн) не уходит — фьеф держит (J1/I3) |
| `phase_caravan` | обозы `Pack` по правилам `caravan_visit`/`caravan_grain_to_ash`: груз, фураж, износ телеги, риск клетки и гибель (`resolve_pack_loss`); излишек еды — выше `need_buffer` 2 мес |
| `phase_day` | только `Pack` в пути: сутки месяца и штатное прибытие по `eta_date`; дворы и экономика не обходят по дням |
| `phase_decide` | выбор действий на следующий месяц |

Домен и надел — **разные стоки времени**: рука, ушедшая на домен, свой надел в
этот месяц не молотит (барщина списывается до `phase_labor`).

### 3a. Время и логистика
`HOURS_PER_DAY = 24.0`; якорь поля: нога 0.65 ч, конь 0.40 ч, обоз 0.85 ч, `arms` 0.8125 ч
(нога ×1.25). `entry_hours = entry_cost × hours_scale`; террейновые пропорции сохраняются,
тропа/грунт/road получают прежние скидки. `find_path` даёт `travel_hours`, `travel_days`
округляет вверх до суток, `travel_months` — производная для лога. `Pack.eta_date` хранится
по суткам, месяц равен 30 суткам; в логе приказа видны `travel_hours`, `days` и `months`.
Месяц остаётся основным тиком; `phase_day` обслуживает только `Pack` в пути (ADR 0078).

### 3b. Каноны текущего среза
Окна §1 не менялись: hill 8–15, two 14–18, shire 24–28. Числа предыдущих срезов —
соль и каноны вида «живые/голод» — **отозваны** и не восстанавливаются: они сняты на
сломанном мире. Действующей измерительной базы сейчас **нет**: ADR 0134 и ADR 0135 устарели
и отозваны (ADR 0143 п. 1), новая база ещё не написана и появится новым ADR после починки
дерева. Соль идёт **от труда и топлива**,
а не от числа гексов: **одна соляная ванна** на место, число работников масштабирует
производство. Сдвиг не подменяется старыми значениями.

### 3c. Соляная дыра и водный v1
Соляный канал работает по ADR 0079/0081: `World.month_events` даёт `caravan_departure`/
`caravan_arrival`, `pack_departure`/`pack_arrival`, `harvest`, `hay_mowed`, `graze`; атрибуция
события идёт по владельцу стока (двору), отток виден, знание приходит только через `Report`,
не по снимку склада. В живых прогонах ненулевые соляные отчёты подтверждены по разным правилам
подсчёта: Table 4/4, 11/11, 10/10; Critic 2/9, 3/15, 1/16. Это разные подмножества одного
канала, а не эталонные числа.

Вода v1: `raft` — 6 единиц груза и 2 взрослых, `boat` — 12 и 4; люди не бесплатны и не едут
в грузу. Фураж на воде — по долям суток (`hours/24`, порция 4.5 + 2.75 за тягло), рейс до 6 ч
без фуража. Портовый сбор 10 % натурой — `Ledger.transfer`, соль exempt. Вода как ресурс и
торговая шхуна вне v1 (ADR 0075).

### 3e. Разведка
`Pack.purpose ∈ {party,scout}`, `profile_id ∈ {hunters,forester,party}`; `tower` не в v1.
Наблюдение физическое и локальное: свой гекс и маршрут — факт без броска, кольцо 1 —
`rng_world` с профилем/покровом, кольцо 2 — слух `confidence=0.5` и `fact=False`, дальше 2
гексов — никогда. Профили: `hunters=0.85` (следы жизни, силён в чистом поле),
`forester=0.75` (лесные знаки, силён в лесу), `party=0.55` (без подготовки). Покров:
лес/топя 1.0, луг 0.75, поле 0.5; `Hazard` ухудшает. Покров и профиль — разные оси.
`observer_id=Pack.id`, `source=scout`; знание и `known_tiles` растут только из доставленного
`Report`. Текст/шум — `rng_news`, физический бросок — `rng_world`; изменение формулировок
не двигает мир. Профили и числа — закрытый закон, пересмотр только новым ADR с замером.

### 3d. Ленивая большая карта
Баронство 100×100 (10 000 гексов) — сценарные данные: 6-связная река, **4 поселения, 150 дворов
(600 человек)**, леса/луга/wilds и редкие маркеры (ADR 0207). Подробно обрабатываются поселения
и `Settlement.works_tiles` (на баронстве — **89 гексов из 10 000**, 0.89 %; замер и команда
в `docs/06_lod.md` §Проверка), стоимость O(поселения); подключение карты к тику — «в работе».
Это не 10 000 агентов и не обещание живого мира. Каноны «живые/голодные дворомесяцы»
из старых срезов **отозваны и не восстанавливаются**; действующей измерительной базы
сейчас нет (ADR 0134/0135 устарели, ADR 0143 п. 1) — окна приёмки объявлены в
`design/scenarios/ACCEPTANCE.md` §1 и §1a.

### 4. Кто чем кормится (пресеты — `docs/07`, `docs/08`)

| Пресет | Надел | Работа | Еда |
|---|---|---|---|
| `holder` / `thegn` | свой | сам не пашет | паёк из амбара своей книги |
| `sokeman` | свой | редкий вызов | надел + фикс. рента 0.6/мес |
| `geneat` | свой | вызов на домен | надел |
| `villein` | виргата (1.0) | барщина 8–16 дней/мес | надел − барщина + гэфоль |
| `cotter` | клочок (0.5) | барщина 4–16 | клочок; не нанимается (двор с наделом) |
| `free_landless` | нет | найм за харчи и серебро | найм; рано уходит, если не нанят |
| `slave` | нет | 20 дней/мес на домене | паёк из амбара своей книги |

**Найм и оплата — отдельно от барщины (ADR 0131).** Барщина — **бесплатный труд**: барон
за неё не платит ни деньгами, ни едой. Хлеб и солома с **бароновой пашни** идут в кладовую
барона; двор с землёй кормит себя сам — **огород и своя скотина**, а при уборке с пашни
забирает остатки. Это **не оплата** и не wages. Нанимается только двор **без надела**,
и получает **харчи и серебро**; двор с наделом не нанимается вовсе.

**Вложенный манор (тэн).** `grant_thegn` переносит право: клетки и дворы уходят
из книги корня в книгу тэна (`Household.manor_id`), режимы не меняются. У каждого
манора свой амбар (`Manor.stock_id`: корень — замок, тэн — `manor:<id>`). Труд,
спрос, найм, гэфоль, паёк, посев и урожай — **по манору двора**: тэн пашет свой
домен в свой амбар, его виллан платит тэну, его раб ест из амбара тэна. Корень
после пожалования от этого двора не получает и его не кормит. Домен/помочи —
только корень. Контракт — ADR 0010.

- **Лесная корзина и готовка.** `roots`, `greens`, `mushrooms` и `berries` — обычные
  съедобные `Good` с местами хранения и рецептами `gather_roots`, `pick_greens`,
  `gather_mushrooms`, `pick_berries`; сбор идёт через обычные действия двора и общий доступ
  к лесу/полю, без нового ресурса. Действие `cook_meal` соединяет зерно или муку с доступными
  добавками в один приём пищи: 2 трудодня, 8 % массы в `sink:waste`, остальное в
  `sink:eaten`; блюдо не добавляется в `goods.yml`. Готовка использует `household.labor_days`
  до `phase_labor`, поэтому двор может осознанно выбрать еду вместо части работы.
- **Сытость и расход.** Вся доступная корзина еды учитывается по массе, а не только по
  зерну; `phase_consume` проходит `NeedConfig.edible_order`, сначала скоропортящееся, затем
  зерно. `food_months` — это `edible_mass / monthly_food_need`; запасы лесных продуктов,
  зерна и мяса взаимозаменяемы в пределах месячной нормы.

### 5. Надел, община, инструмент

- **Ёмкость клетки: кап стойла, не кап пашни.** Фиксированного предела партий на клетке
  **не существует** (ADR 0173 п. 2, ADR 0137): пашню ограничивают труд двора и стоячая
  материя клетки, а не регламент. `manor.yml::plot_batch_cap_per_tile` = 4 — **кап стойла
  скота на клетку в месяц**, единственное живое чтение — `economy/labor.py::_tile_batch_cap`
  (ADR 0143 п. 2). Виргата/клочок (`holding_scale`) — доля двора в выходе гекса, а не
  потолок: двор берёт столько партий, сколько ему по силам на этой доле своего труда
  (ADR 0137 п. 4). Общий счёт клетки делят держатели (`_held_tile_ids`: усадьба и `Right`)
  — только при косьбе сена, не в пашне и не в общинном сборе (§9). Проверка:
  `test_bloom_and_hay`, `test_draft_livestock`.
- **Общинный сбор.** `waste`/`reserved_wood` — не держание, а право ДОСТУПА:
  `has_access_to_communal_tile` принимает только `Settlement.works_tiles` или клетку с
  `Right.kind = common` для двора либо его поселения. Соседство даёт встречу и путь,
  но не communal-доступ; `own_tiles` и `_held_tile_ids` не меняются. Капа 4 на общинном
  сборе **нет** — его отменил ADR 0173 п. 2 вместе с делёжем партий между дворами одной
  клетки. Держит правило другое: стоячая материя общинной клетки общая,
  поэтому ни один двор не берёт «полную виргату» (ADR 0060, ADR 0068, ADR 0077).
  `common` не становится индивидуальным наделом; `grazing` остаётся личным держанием.
  Чужой двор без `works_tiles`/`common` доступа не имеет. Проверка:
  `test_common_right_access`, `test_communal_access` (ADR 0077).
- **Племя v1.** `Tribe.settlement_id` связывает `native_village` с `Settlement`; состав
  берётся из `Settlement.household_ids`, поэтому поля состава или отдельной книги в `Tribe`
  нет. Двор племени — `free_landless`, но `phase_migrate` не даёт ему уйти самому.
  По ADR 0116 и ADR 0140 племя **не вассал и вне книг барона**: до принятия в солидарности
  оно не несёт оброков, повинностей и службы, не платит дань и не получает подачу —
  повинностей **0**; единственные ворота — принятие в солидарности, после которого племя
  становится обычной деревней барона и оброк
  появляется только при `vassal` и `tribute_grain = 0.6` как фиксированный натуральный
  `levy` 0.6 зерна/мес на каждый живой двор. До солидарности оброк не создаётся вовсе.
  `muster_kits` ограничивает потенциал
  вызова и не создаёт `Pack` или действие. Проверка: `test_tribe_v1`, `test_tribe_economy`.
- **Инструмент.** Выход жатвы: нет инструмента 1.0 < `wooden_plough` 1.05 < `iron_share`
  1.15 (`tool_yield_factor`, `TOOL_YIELD_FACTORS`). Инструмент — материя: железный лемех
  выдаётся из стока лорда переводом (`engine/manor.py::grant_tool`), а железо идёт
  рецептами `smelt_iron_bloom`/`smith_iron_share` в очереди `idle_repair` (гейт сытости,
  ADR 0037); деревянный плуг и телега — рецептами `craft_wooden_plough`/`craft_cart`. Проверка:
  `test_grant_tool`.
- **Тягло (ADR 0025).** Вол/конь удешевляют ТРУД партии `harvest_grain` (вол ×0.7,
  конь ×0.9 — хуже вола, осёл/молодняк ×1.0; `economy/livestock.py`). Без тягла плуг
  живёт за полный труд. Воз: осёл ×1.2 ёмкости, конь ×1.3 и дни ×0.75 поверх телеги
  (`origin_draft`); вол воза не знает. Проверка: `test_draft_livestock`.

### 6. Обмен между поселениями (обоз)

Обоз — реальный `Pack`, а не только `Report` (A1/H). Правила — `SpawnRule` с
`target=pack` и `params.kind=caravan` (`economy/caravan.py::caravan_rules`):

- `caravan_visit`: соль `salt_village → hill_court`, каждые **3** мес, `cargo_amount` 4.0.
- `caravan_grain_to_ash`: зерно `hill_court → ash_village`, каждые **4** мес, `cargo_amount` 6.0.

Груз уходит со стоков origin в сток воза (`caravan_load`), фураж — в `sink:eaten`,
остаток — в склад назначения (`caravan_unload`); материя не создаётся (`external_in 0`,
телепорт household→castle 0). Съедобный груз (зерно) не вывозится ниже
`need_buffer_months` 2.0 месячной нужды живых дворов origin (`caravan_below_buffer`) —
посев и зима не продаются; соль — не еда, буфера нет. Цен нет вовсе: `barter_memory`
(ключ `origin->destination:good`) хранит `carried`/`delivered`/`ratio`/`lost`, где
`ratio` — доля доехавшего груза, а не меновое число. На рейсе телега изнашивается
(`cart_wear` 0.05, ломается ниже 0.5, `cart_broken`), риск опасной клетки рассеивает
долю груза (`loss_share` 0.25), катастрофа 0.25 губит воз целиком через
`hazards/travel.py::resolve_pack_loss` (груз — в стоячий сток клетки, `status=lost`,
`silence`). **Маршрут строит `find_path` профилем `caravan`** (ADR 0029): возницы землю
знают (`known=None`), дорога/брод/мост дешевят и живой обоз, река без переправы
непроходима; нет пути — воз не идёт. Часы — сумма часов входа из `find_path`; сутки
округляются вверх, месяц — производная для лога. Ёмкость с
телегой ×1.5, без неё ×0.6 и время ×1.5; тягло поверх (осёл ×1.2, конь ×1.3 и время ×0.75).
Фураж и риск — по клеткам после origin. Игрок
видит обоз только через `Report`. Проверка: `test_caravan_h`, `test_caravan_trade`,
`test_barter_memory`, `test_caravan_module`.

### 7. Платежи и материя (только `transfer`)

- **Рента/гэфоль.** Сокмен — фиксированный `fixed_rent_grain_or_pence` 0.6/мес
  (Obligation). Виллан — `in_kind_martinmas` 4 зерна в мес 11. Это **не доля
  всего добытого**.
- **Оброк — доля от урожая двора (ADR 0183).** База оброка живёт в `obligations.yml`
  записью вида повинности `id: rent_share`: `kind: rent`, `due_good: grain`, `basis: share`,
  `default_share: 0.1`. Размер оброка — **доля урожая ПРОШЛЕГО месяца двора**
  (`default_share × урожай прошлого месяца`), а не сумма и не доля текущего остатка
  амбара (ADR 0192). Формула множителя прежняя: зерно 10.0 → оброк 1.000,
  20.0 → 2.000,
  40.0 → 4.000, 0.0 → 0.000. **Размер читается по `kind`, а не по id**, поэтому переименование
  записи в каталоге код не рвёт, а удаление записи роняет мир. **Доли нет в каталоге —
  падение, а не подстановка числа** (`ValueError`). Число `Right.rent_share` **размером больше не
  является**: по нему решается только одно — понесёт ли наделение оброк (`rent_share: 0.0` носят
  общинный выпас, собственный выпас барона и наделения племени в солидарности). Поэтому
  `rent_share` 0.1 и 0.9 дают одинаковый оброк, а при 0.0 оброк не заводится вовсе.
  **Остаточная зависимость от сцены признана:** сценарий всё ещё решает, понесёт ли наделение
  оброк, — перенести этот выбор в каталог нельзя без правового поля, которого нет.
  Проверка: `test_legal_manor_hiring::test_grant_tenure_creates_villein_status_and_rent`,
  `test_catalog_rules` (запись вида повинности грузится и ссылается на существующий id).
- **Оброк — доля урожая ПРОШЛЕГО месяца, и лаг в месяц — закон** (ADR 0192). Нельзя брать
  оброк с зерна, которое ещё не обмолочено; месяц запаса означает, что двор не требует
  подати с урожая, посыпавшегося в середине сезона. **Оброк — долг за то, что двор дал
  в долг, а не предъявление счёта в тот же день.** База — **урожай**, а не текущий
  остаток: с остатка платилось бы и за привезённое, и за старое, и за подачу, а это уже
  не доля урожая. Статус: **в коде не исполнено** — `household_rent_base`
  (`legal/obligations.py:82`) отдаёт текущий остаток амбара, трекера урожая в дереве нет.
  Проверка долга — команда обязана вернуть 0 строк:
  `grep -rn "прошлого месяца\|last_month" sim/src/hillcourt/legal/obligations.py`.
  Косвенное подтверждение, что лаг вынужден: `phase_consume` (9) идёт раньше
  `phase_obligations` (11), и двор съедает урожай раньше, чем платить — в стенде
  `start_stand` к фазе оброка зерно двора равно 0.000.
- **Оброк пересчитывается помесячно, а не застывает в момент выдачи наделения.** Начисление
  ведётся от урожая прошлого месяца (ADR 0192), а не от остатка и не
  на текущий, а не фиксируется один раз при `grant_tenure`
  (ADR 0185, назначен юристу). Проверка:
  `test_legal_manor_hiring::test_rent_is_share_of_harvest_not_of_stock`.
- **Паёк.** Амбар СВОЕЙ книги → двор (`board_grain_per_adult` × `monthly_food_need`
  двора × буфер против порчи) рабу/лорду; чужой амбар не кормит (G2).
- **Посев гэфоль-акров** (мес 10–11). Зерно из амбара виллана → стоячая материя
  поля домена его манора.
- **Потолок закупки зерна.** Двор покупает у барона не больше `monthly_food_need` зерна
  в месяц — своей месячной нормы, суммарно по всем каналам, по зерну из амбара барона;
  серебро и натуральный обмен считаются одним счётчиком, relief в лимит не входит
  (ADR 0144, ADR 0139). **Потолок — страж, а не причина голода** (ADR 0160): держат голод
  подача, паёк и жалованье найму, а не покупка.
- **Найм.** Нанимаются **только безземельные** (`land_relation = landless`): двор с рабочим
  наделом не нанимается, он работает своё хозяйство, и его доход это надел. Условия: домен не
  закрыт барщиной и у амбара своего манора есть зерно. Выплата — **харчи зерном и зарплата
  серебром** одновременно, не «зерно или серебро»; серебра может не хватить, тогда зарплата
  частичная, а харчи платятся. Барщина при этом остаётся **бесплатным трудом** и оплаты не
  имеет (ADR 0131).

### 8. Решения двора (один выборщик)

`economy/decisions.py` — один выборщик на все пресеты; набор действий — из
пресета (`allowed_action_ids`). Порядок: подмога при голоде → еда → зимнее
топливо → починка → скот → риск. Авантюризм = интерес − страх − цена рук на
поле. Держатель любого манора (корень и тэн) не уходит — фьеф держит (J1/I3);
`tied` (виллан/коттер) не уходит легально; свободный вне книги (`free_landless`,
часть сокменов) уходит.

**Порядок рецептов двора: еда → топливо → прочее, и он не алфавитный** (ADR 0161 п. 1).
Двор без дров зимой мёрзнет, двор без планки — просто беден, поэтому в `_recipe_order` после
едовых рецептов идёт класс **топлива** (`cut_firewood`, `cut_peat`, `split_logs`) и только
потом всё остальное, включая `make_board` и `make_plank`. Нового поля приоритета в онтологии
нет: это порядок, а не свойство рецепта. Проверка: `test_start_stand`, `test_household_economy`.

### 9. Износ и природа

- Топор тупится только на «топорных» рецептах (`needs.tool.wear_recipes`), масса
  уходит в `sink:waste`; ниже порога ломается.
- Свинья плодится только при паре (`pig ≥ 2`) и расходует производителя.
- Тягло (ADR 0025, оживлено ADR 0030): три вида с полом в стоке (`ox_m/ox_f`, `donkey_m/donkey_f`,
  `horse_m/horse_f`; молодняк `ox_calf/donkey_foal/horse_foal`; общего `horse`
   нет). Корм сезонный (правка хозяина, цикл 19; ADR 0053/0055): зимой — сено полной
   нормой из своего стока, летом (мес. 5–9) — 30 % сеном + 70 % выпасом
   (`graze_for_herd`); выпас — только из стоячего сена пастбищ и не больше кормовой
   ёмкости клетки (пастбище 2.0/мес, остальное 0 — `pasture_forage_capacity`, только
   чтение), перевод в `sink:eaten` (причина `graze`); недобор выпаса — снова сеном из
   стока, затем падёж прежней пропорцией; бесплатной травы нет. Пастбища стада:
   амбар — клетки книги, склад — клетка + `works_tiles`. Косьба — единственная, ранней фазой `phase_hay`
  до поля (поздний добор в `livestock_month` удалён, ADR 0050), только при нехватке
  (`gather_draft_hay`, рецептом `gather_hay`; труд — из остатка, нового не создаётся; партии идут в общий кап клетки
  (тот же кап 4, счётчик свой на фазу стада; набор клеток `hay_pastures` — свой надел +
  соседнее общинное пастбище — исключение); износ топора косьбой не идёт — только партии
  `work_month`, исключение ADR 0030); приплод редок (0.08/мес на пару, родители — условие, кобыла цела),
  взросление за сено (пол — жребий), падёж возможен (0.005/0.01). Конь — только у
  свободных и только свободным даёт тягло/воз (`draft_goods_for`, проводка `can_hold_horse`
  в `decisions`; `tied`-двор с конём бонуса не получает); рабочий конь нормой
  тэна не считается (только `war_kit`). Выгода тягла — там, где вяжет труд, а не кап
  партии: `holding_scale` — доля **труда** двора на своём наделе
  (`plot_labor_left = holding_scale × budget`), а не целое число партий, поэтому у двора
  с `holding_scale` 0.5 рук на пашне вдвое меньше, и пока труда хватает, тягло входит в
  труд партии (`plough_factor`), а партий выходит больше; `VIRGATE_BATCHES` — верхняя
  граница партий, не кап клетки (ADR 0030, ADR 0137 п. 4). **Порог тягла замерён
  (ADR 0151):** одна пара волов (2 головы) за сентябрь — клочок 13.60 → 21.99 зерна, виргата
  27.20 → 43.99, это **+62 % и +62 %**; партий от числа волов не растёт — клочок **3 партии**,
  виргата **5** при любом числе волов от одной пары, потому что `holding_scale` входит в труд,
  а не в число партий. Потолок прибавки `draft_yield_cap` 1.30 достигается на **6 головах**:
  4 головы — 2.64 сена/мес, 6 — 3.96, 8 — **5.28 сена/мес при нулевом приросте зерна**, то
  есть с четвёртой пары тягло — чистый расход сена. Навоз поверх тягла прибавляет сверху
  (×1.3085 против ×1.264) и партий не добавляет. Дельта материи **0.0** во всех замерах.
  Проверка: `test_draft_livestock`, `test_soil_improvements`. Шир стартует с тремя парами
  (волы `hh_11`-виллан, ослы `hh_14`, кони `hh_09` — конь у свободного) и запасом сена;
  критерий пар — анти-голод (`starved` = 0 за 12 мес, естественный падёж допускается).
- Железо (ADR 0030, проводка засвидетельствована ADR 0037): рецепт `smelt_iron_bloom` (`iron 1.2 +
  firewood 0.6 → iron_bloom 1.0`, труд 10, баланс 1.8 = 1.8) закрывает И-7; рецепт
  `smith_iron_share` официален (`iron 1.2 + firewood 0.6 → iron_share 1.0`, труд 8) и
  подключён в очередь `idle_repair` (после топора и крицы); дорогое — только сытому при
  входах (гейт), бонус выхода держится `tool_yield_factor` (1.0/1.05/1.15 — числа не
  тронуты).
- Резерв косьбы (E1) удалён (ADR 0050): `_mow_reserve` жала поле под добор, который
  не косит, — полю теперь все руки; ранняя косьба `phase_hay` цела. Голодный кормит
  семью, не скот.
- Рубка рядом (E3): `cut_firewood`/`cut_wood`/`mine_iron`/`cut_peat` разрешены на соседнем
  лесу/топи без спавна; стартовый `log`/`works_tiles` — в сценарии.
- **Лестница материалов — в каталоге (ADR 0157).** `log → board → plank`, ниже не спускаемся
  (ADR 0106 п. 3). `board` и `plank` — товары в `goods.yml` (`storage: barn`), `make_board`
  и `make_plank` — рецепты в `recipes.yml`, входящие в `recipes:` действия заготовки
  `cut_wood_if_allowed`, поэтому двор **может** распилить бревно на доску и доску на планку.
  Потребителя планки пока нет и это не дыра: цепочке хватает места хранения и производства
  (И-7), планка лежит на складе. Код **не дописывает** товары в каталог: `_ensure_material_ladder`
  удалена, поле `Good.material_quality` удалено как поле с нулём чтений, двенадцать `DEFAULT_*`
  в `economy/soil.py` удалены — **`spawn_rules.yml` единственный источник**, и отсутствие
  ключа в `grow_grain.params` теперь **ошибка загрузки**, а не тихая подстановка числа. Проверка:
  `test_catalog_rules`, `test_household_economy`, `test_price_table`.
- **Цена считается по полной себестоимости входа (ADR 0161 п. 1),** а не по дневной ставке:
  сырьё и потери берутся из входа целиком, дневная ставка входит только через труд. Итог уже
  сложен в `Good.price_silver`; коэффициент дефицита — по классу: **1.1** для материала
  местного изобилия (`log`, `firewood`, `peat`, `hay`, `board`, `plank`), **1.2** для зерна и
  топора, **1.3** для соли и железа. Отдельного поля коэффициента в каталоге нет. Проверка:
  `test_price_table`.
- Покупка (E4/E7, соседский торг — ADR 0057): сначала свои пары клетки, затем чучие пары
  кластера (кластер — клетка + 4 ортогональных; каждая клетка ровно в одном, двойных
  сделок нет; носитель — двор, порядок по id): фикс-цены — бревно 0.5 зерном
  (кап 4), скот за зерно (вол 8, осёл 5, конь 12; молодняк дешевле), свинья 3.0 серебром;
  **цена зерна — каталожная** `goods.yml::grain.price_silver` = **0.128165**, констанды в коде
  нет (ADR 0144); цена носителя — сбор 0.5 (`PORTER_FEE`) там, где покупатель сыт
  (свиньи/брёвна/скот), на голодном зерне — укус 0.25 (`PORTER_BITE`) с богатой стороны
  в отход; зерно через клетку ≤ 2.0 (`NEIGHBOR_GRAIN_MAX`); дар — без цены. Только
  `Ledger.transfer` + потери; продаётся излишек сверх пары (пара неделима), конь —
  только свободному; серебро из ничего не создаётся. Дальше соседнего кластера —
  только обозом-`Pack`. Спавн — отложен.
- **Потолок закупки зерна (ADR 0144) — страж, а не причина голода (ADR 0160).** Двор может
  купить у барона **не больше `monthly_food_need` зерна в месяц** — своей собственной месячной
  нормы, суммарно по всем каналам. Считается по зерну, **вышедшему из амбара барона**,
  независимо от способа оплаты: серебро и натуральный обмен (ADR 0139) идут через **один и
  тот же счётчик**, иначе обмен натурой стал бы обходом потолка. Relief (подача) в лимит
  **не входит** — это отдельный правовой акт (ADR 0139). Отдельного потолка прилавка нет: он
  следует сам, прилавок не продаст больше, чем могут купить дворы. **Зачем:** без потолка один
  двор на завышенной цене выкупил бы весь амбар за месяц и обнулил рынок — потолок нужен,
  чтобы рынок вообще можно было включить. Голод он **не держит**: держат голод `relief`,
  `board` и `hire` — замер 60 месяцев × 4 сида дал из амбара барона подачу 1954.25, паёк
  663.20, жалованье 345.48 и покупку **0.00**, превышение потолка на двор за месяц
  **0.000000000**. Потолок и сейчас не режет ничего, и это норма, а не дыра: канал берёт по
  надобности. Второй ограничитель — серебро: без него двор не покупает, сколько бы ни хотел
  (ADR 0101). Проверка: `test_baron_granary_sale`, `test_barter_memory`, `test_price_table`,
  `test_caravan_h`.
- Пул барщины (E6): спрос манора капирует пул (`_render_pool`); дни без доменных клеток —
  в `wasted_labor_days`, рабы вне капа.
- Смертность и роды (E8 + ADR 0031): `_die_by_age` + `needs.yml:death` (ставки низкие,
  баланс держат роды); расцвет в иммунитете для сценарных грантов (скрипты не падают);
  характер новорождённого — из хеша id (не ест `rng.economy`, жребий трио цел); люди —
  не материя.
- У 11 из 12 правил появления материи есть `cap_per_tile`: природа не бездонный кран.
  Исключение — `grow_grain`: потолка у зерна нет намеренно (ADR 0137 п. 2, ADR 0142 п. 3),
  клетка копит стоячего зерна столько, сколько успевает снять уборкой. Проверка:
  `test_household_economy::test_grain_growth_has_no_cap_per_tile` (зерно без потолка),
  `test_household_economy::test_every_other_growth_rule_is_capped` (остальные 11 — с потолком).

```bash
bash sim/run_tests.sh

```

Критерий: все тесты зелёные; в логе видны `travel_hours`, `days` и `months`; прогон
36 месяцев завершается с `дельта материи 0.000000`; приёмочной измерительной базы
сейчас нет (ADR 0134/0135 устарели и отозваны, ADR 0143 п. 1) — числа прежних срезов
не подставляются в критерий, новая база появится новым ADR после починки дерева.
Ревизия Scribe: каждое правило из §10 имеет файл-источник и тест.
