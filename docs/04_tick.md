# 04. Тик

## Назначение

Порядок фаз и цена решений. Основной тик — **месяц**. Дневной контур — исключение для пути и инцидента.

## Правила

### Фазы месячного тика (порядок фиксирован)
1. `phase_season` — сезонный множитель урожая по номеру месяца. Материю не трогает.
2. `phase_growth` — календарные `SpawnRule` с `target=good` вносят стоячую материю
   (`Ledger.external_in` с `rule_id`), умноженную на сезонный множитель и **ограниченную
   `cap_per_tile`**: природа не бездонный кран.
3. `phase_manor` — манор до работы двора на своём наделе (`economy/manor.py`): двору
   возвращается месячный запас труда (взрослый = 20 трудодней), сезонная барщина
   (`legal.calendar.seasonal_labor_days`) и рабы уходят в пул **своего** манора; паёк
   рабу/лорду выдаёт амбар его манора; при недоборе манор нанимает `free_landless`/лишних
   коттеров за еду/пенс; собирается фиксированный гэфоль и посев гэфоль-акров в домен того
   манора, которому двор должен; каждый манор снимает урожай своего домена в **свой** амбар
   не больше спроса. Корень — `settlement:hill_court`, тэн — `manor:<id>`; у тэна в конце
   фазы работает `thegn_month` (сборка `war_kit`, вылазка на кольцо). Если у манора есть
   трудодни, но нет доменных клеток — `wasted_labor_days` в логе. **Недобор в пике —
   недобор урожая этого домена, а не магия.** Помочи — только корень.
4. `phase_hay` — ЕДИНСТВЕННАЯ косьба тика (ADR 0050; контракт — docstring
   `engine/tick.py::phase_hay`, правка кода — заход Implementer): дворы с тяглом косят
   `gather_hay` из остатка труда после барщины, до поля; поле худеет честно — сено
   первое (ADR 0032). Поздний добор в `livestock_month` и резерв `_mow_reserve` удалены
   замером (добор за 60 мес накосил 0, резерв жал поле под добор, который не косит).
   Без тягла фаза пуста, RNG не тратится.
5. `phase_roadworks` — стройка пути (`engine/roadworks.py`, стоимость клетки — ADR 0039,
    кап — ADR 0067): в активные проекты дороги/брода/моста добирается остаток рук после
    барщины, до `MONTHLY_LABOR_CAP` = 40 трудодней/мес на проект (дорога 20, брод 14,
    мост 28 дней), материал (`log` 3/2/4) уже списан при `start_work`.
   Дни, ушедшие сюда, двор на своём наделе не отработает (`phase_labor` худеет честно).
   Завершение один раз поднимает tag `road`/`ford`/`bridge`; пока проект не готов — клетка
   старая. Без работ фаза — no-op, канон не двигает. Отмены и возврата списанного при
   `start_work` материала нет; начатая работа завершается записанным `manor_id`, даже если
   клетку позже пожаловали тэну (дорога следует за трудом; перекройка книги под стройку —
   отложено).
6. `phase_labor` — `Household` отрабатывает своё решение: главное и мелкое действие из
   `actions_household.yml` разрешают набор рецептов. Рецепты применяются, пока хватает труда,
   стоячей материи и входов (сначала рецепты еды, затем по `id`). Земли двора — только надел,
   который его кормит (`regime.feeds_household`); домен лорда сюда не входит, сбор
   (`forage_wild`) — только с соседних клеток. Списываются `Tile.standing_stock_id` и `labor_days`
   (с учётом `seasons.yml` — выход на 1 оставшийся трудодень), результат идёт в `Stock`,
   потери — в `sink:waste`. Топор тупится, его масса уходит в `sink:waste`; ниже порога ломается.
7. `phase_spoil` — порча по `Good.spoil_per_month`, в `sink:waste` (включая тайники двора).
8. `phase_consume` — еда: `Stock` → `sink:eaten`; при нехватке растёт `hunger_days`. Зимой
   сжигается топливо, скот кормится сезонной нормой (зимой полное сено, летом 5–9 —
   30 % сено + 70 % выпас `graze_for_herd` с краем ёмкости и стоячего, перевод в
   `sink:eaten`; без корма гибнет пропорционально нехватке);
    в конце фазы — `livestock_month` (приплод, взросление, падёж, выпас; добора сена
   косьбой больше нет — единственная косьба фазой `phase_hay` до поля, ADR 0050/0055).
9. `phase_demography` — люди, не материя (`economy/demography.py`, ADR 0031/0033): старение
    всех на месяц, недоросли входят в тягло через 30 мес (`maturity_months`), роды
    у дворов с устойчивым излишком (`food_months ≥ 5.0` восемь месяцев подряд, взрослых
    ≥ 2, ртов < 8). Новорождённый — `child` (0.7 рта), рук не даёт; Ledger не трогается,
    дельта обязана быть 0. Характер новорождённого — из хеша id (`hashlib.md5`), общий
    `rng.economy` не естся (жребий трио цел); потоки на стойло — долг следующего ADR.
10. `phase_obligations` — `Obligation`: платёж (`Stock` → двор), иначе растёт `arrears`.
    Трудовая повинность здесь только записывает сезонный долг (`duty_days`/`corvee_days`),
    руки с надела снимает `phase_manor`. **Ушедшие дворы (`left_at ≠ None`) пропускаются.**
    `muster` обслуживает срок 2/3 месяца от даты выхода; outbound↔return — одна повинность,
    `call_status` различает службу, возврат, просрочку и невозможность; потеря/тишина не равны
    отказу.
11. `phase_exchange` — подмога из стока замка, тайники от волков, локальный обмен на клетке
   (свиньи за серебро, зерно между сытым и голодным). Только `Ledger.transfer`.
12. `phase_hazard` — сначала топ-ап существующих угроз по правилам `target==hazard,
   mode==topup` (сейчас только `wolves_den`: всё числовое — из `params` правила,
   бросок `base_prob` потоком `rng.hazard`, рез потолками; новых сущностей `Hazard`
   нет, материя не двигается — ADR 0042/0043). Подросшая стая крадёт уже в этом
   месяце: далее волчья кража зерна и риск пути по опасной клетке (можно потерять
   человека); волчья кража на клетке мира усадьбы корня (радиус 1 от зала)
   умножается на `peace_theft_factor` 0.5. Каждый рост метится для Info
   (`wolves_den_topup[_<hazard_id>]` в `world.stats`); саму весть рождает
   `phase_inform` (`report_pending_topups`, ADR 0044, см. `docs/05`). Затем рождение
   ватаги по правилам `target==hazard, mode==spawn` (сейчас только `band_camp`,
   ADR 0045/0046): гейт каждый тик без кэша (топь + ≥3 живых дворов на клетке),
   поверх активной угрозы того же вида не сеем; бросок `base_prob` потоком
   `rng.hazard` по прошедшей гейт клетке; рождение `intensity_init`/`population_init`,
   рез потолками, `spawn_rule_id` — честный id правила, материя не двигается.
   Рождение — только с вестью, структурно: сущность + метка
   `<rule_id>_birth_<hazard_id>`, синхронный вызов `news.threats.report_pending_births`,
   весть о клетке рождения в ответе — иначе откат. Новорождённые крадут уже в этом
   месяце. Появление руин по `SpawnRule` — отложено (см. `docs/02`). Обозы-`Pack`
   рождаются в `phase_caravan`.
13. `phase_migrate` — решение `intent`: двор уходит на соседнюю клетку, если
    `hunger_days ≥ 3` **или** `Obligation.arrears ≥ 3 × due_amount`; без pathfinding;
     ушедший двор обратно не возвращается автоматически. Племенной guard доходит обратным
     lookup через `Settlement.kind = native_village` и `Settlement.household_ids`: двор племени
     не уходит сам даже при голоде. Обычный двор-пресет без `can_leave` (например `villein`,
     `cotter`) также не уходит сам (см. `docs/07`); полный сосед (кап 5) не выбирается — двор
     остаётся (движение садится через `settle_household`).
14. `phase_caravan` — отправка обозов по каденции и разгрузка дошедших (`economy/caravan.py`):
    соль деревня→замок (правило `caravan_visit`, 3 мес) и зерно холм→деревня у ясеня
    (`caravan_grain_to_ash`, 4 мес) едут как `Pack` со сроком `eta_date`, а не телепортом.
    В пути воз ест фураж (`fodder`), телега изнашивается и ломается (`cart_wear`/`cart_broken`),
    риск опасной клетки может рассеять долю груза, а катастрофа губит воз целиком через
    `hazards.travel.resolve_pack_loss` (груз — в стоячий сток клетки, `silence`, `status=lost`).
    Съедобный груз берётся только выше `need_buffer_months` (2.0); итог рейса пишется в
    `barter_memory` (`carried`/`delivered`/`ratio`/`lost`) — цен нет, `ratio` это доля груза.
    Игрок видит обоз только через `Report`. Маршрут живого обоза строит `find_path` профилем
    `caravan` (возницы землю знают, туман игрока здесь не применяется, ADR 0029), поэтому
    дорога/брод/мост дешевят и его, а река без переправы непроходима; нет пути — воз не идёт.
     Дни, фураж и риск считаются по клеткам маршрута (`len(route)-1` входов), а не по манхэттену.
     Время пути хранится как `travel_hours`; `days = ceil(travel_hours / 24)`, а месяц — производная
     для лога. `eta_date` считается по суткам, месяц равен 30 суткам; дробные сутки округляются
     вверх. В логе приказа остаются `travel_hours`, `days` и `months`. Дошедшие живые обозы
     кормят память дорог (`remembered_road_tiles`):
    приказы могут идти по их клеткам и через неизвестное — задокументированный механизм
    пути, не чтение запасов (И-3). После разбора обозов и дошедших `Pack` завершённая ходьба
    топчет клетки прихода; вес задаёт вид движения: `caravan` 4.0, `party` 2.0,
    `household_move` 2.0. Тропа возникает при `Tile.trail_wear ≥ 3.0`, грунтовка — при
    `Tile.trail_wear ≥ 12.0`; вода и `Tile.road` не топчутся.
15. `phase_travel` — дошедшие до `eta_date` посылки `Pack` разрешаются (`hazards/travel.py`):
     `resolve_migrations` доводит ушедший двор (`Pack kind=household_move`, A3) — клетка меняется
     только по прибытии, при потере людей рождается `messenger`, при полной гибели `resolve_pack_loss`
     кладёт груз в стоячий сток и рождается `Report` с `source=silence`; `resolve_packs` разбирает
     прочие посылки (опасность клетки может унести людей). Известие не приходит из пустоты: нет
     вести — `silence`. Шаг — только на соседнюю клетку. После разбора дошедшие `Pack` топчут
     клетки прихода своим видом движения; ходки получают вес 1.0 и топчут после
     `plan_next_month` в `phase_decide`.
16. `phase_day` — дневной контур только для `Pack` в пути: проходятся сутки месяца
     (1..30), и для каждой `in_transit` посылки с `eta_date` внутри месяца вызывается её
     штатный разбор с датой прибытия. Дворы и экономика остаются помесячными; месяц остаётся
     основным тиком (ADR 0078, И-4).
17. `phase_decide` — выбор `main_action`/`minor_action` на следующий месяц: подмога при голоде,
     еда, зимнее топливо, починка, скот, риск. Набор действий — из правового пресета
     (`allowed_action_ids`); авантюризм = интерес против страха и цены рук. После
     `plan_next_month` ходки `Household.traveling` топчут клетку прихода с весом 1.0.
18. `phase_inform` — факты месяца превращаются в `Report` с задержкой, шумом и искажением
    (`info/briefing.py`, см. `05`); затем `make_seat_eye_reports` кладёт `Report eye_from_hill`
    о клетках радиуса 1 от зала корня (задержка 0, `grain_approx`, вид `Hazard` без численности).
    Пустое поселение не превращается в активное племя: дворы без живых людей не дают ему
    форму или знание.
19. `phase_record` — снимок состояния и запись в лог. После снимка все сухопутные клетки
    теряют `0.5` единицы `Tile.trail_wear`; вода и клетки с `Tile.road` обнуляются.
    Материю фаза не трогает.

### Цена сухопутного прохода
`find_path` применяет множитель `Tile.trail_wear`: 1.0 для целины, 0.9 для тропы
(`trail_wear ≥ 3.0`) и 0.8 для грунтовки (`trail_wear ≥ 12.0`). Вода и `Tile.road` имеют
собственные цены; речной маршрут не топчется и не получает сухопутный вес. Профиль движения
выбирается строкой `MOVEMENT_PROFILES`, включая `arms` и `rider`; иных классов профилей нет.
Пересечение порога вверх при топтании записывает в `world.stats` счётчики
`trails_born`/`dirt_born` и метки `trail_born_<tile_id>`/`dirt_born_<tile_id>`; затухание
метки не создаёт (ADR 0061).

### Честное время пути
`HOURS_PER_DAY = 24.0`; якоря поля: нога 0.65 ч, конь 0.40 ч, обоз 0.85 ч, `arms` 0.8125 ч
(0.65 × 1.25). Для профиля `hours_scale(profile) = field_hours / day_field_cost`, а
`entry_hours = entry_cost × hours_scale`; поэтому террейновые пропорции, тропа ×0.9,
грунт ×0.8 и `road` как минимум не дублируются. `find_path` возвращает часы, `travel_days`
округляет часы вверх до суток, `travel_months` — производная для лога. `Pack.eta_date`
считается по суткам через `advance_days`; месяц равен 30 суткам. В логах приказа присутствуют
`travel_hours`, `days` и `months` (ADR 0078).

### Дневной контур
В v0 **не реализован** (отложено). Запрет И-4 держится: обхода всех `Person` нет. Когда контур
появится, он включается **только** при `Pack.status = in_transit` или активном `Hazard` и
итерирует лишь эти сущности, не всех `Person`.

### Детерминизм
Случайность — через именованные потоки: `rng_economy`, `rng_world`, `rng_news`, `rng_hazard`.
Порядок фаз и порядок сущностей (сортировка по `id`) фиксированы, иначе `seed` не гарантирует
результат (И-6). `state_hash` покрывает дату, стоки, поля дворов (включая `mood` и
`legal_status_id`), режимы клеток, опасности (`population`/`satiety`), права, посылки,
повинности (`paid_total`/`arrears`/`corvee_days`), возраст и стрики дворов
(`age_months`/`food_streak`/`birth_count`), `Tile.trail_wear`, теги пути
(`road`/`ford`/`bridge`), службу манора (`service_*`/`mustered`), место стола (`seat_*`) и
доставленные `Report`.
Активные стройки (`World.roadworks`) входят условными частями (`way|`/`roadwork|`), только
пока непусты: пустые работы канон не сдвигают.

### Материя
Материя не берётся из ниоткуда: `phase_labor` переводит `Tile.standing_stock_id` → `Stock`, `phase_growth`
вносит внешний приход по `SpawnRule` (`external_in` с `rule_id`), потери и потребление идут
в `sink:*`. Материал стройки пути (`log`) списывается при `start_work` переводом амбар корня →
`sink:waste` (`roadwork_material`), не создаётся и не телепортируется. `test_matter_conservation`
проверяет сумму всех `Stock` за прогон.

## Проверка

```bash
bash sim/run_tests.sh
PYTHONPATH=sim/src python3 -m unittest sim.tests.test_travel_hours -v
```

`test_travel_hours.py` — часы, сутки, ETA и `phase_day` только для `Pack`;
`test_tick_runs.py` — месячный тик и повтор с тем же `seed`; `test_matter_conservation.py` —
сумма материи за прогон не меняется.
