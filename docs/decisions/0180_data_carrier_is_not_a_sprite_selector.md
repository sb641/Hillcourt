# 0180. У плитки есть носитель данных, а не селектор спрайта; и это проверяется

Исправляет формулировку ADR 0178 и добавляет проверку, которой не было ни в 0136, ни в
0170, ни в 0171, ни в 0172. Старые ADR не редактируются, поэтому ошибка исправляется здесь,
а не там.

## Контекст

Задача была сформулирована как «закрыть дыру с носителем у трёх keyed-плиток». Проверка кода
показала, что дыра шире и что я сам в ADR 0178 написал неправду.

**Факт первый: селектора спрайта не существует вовсе.**

```
grep -rn "sprite|icon|atlas|plate_px|texture" sim/src/hillcourt/ --include=*.py
(ноль совпадений)
```

`client/` заморожен, и в `sim/` нет ни одного места, которое выбирает картинку. Сам
`tile_view.py` говорит об этом в первой строке: он «снимок для иконки, **не рендерер**», и
«из него **потом** рисуют иконку». Формы в нём — строки для лога и дампа, а не имена
спрайтов.

**Факт второй: формулировка ADR 0178 была преувеличением.** Там написано: «Carrier: рантайм
может выбрать по нему плитку». Неправда: рантайм может **прочитать** `Person.age_class`, но
ничего **не выбирает** по нему плитку. Это ровно тот класс обещания без носителя, который
репозиторий уже наказывал в ADR 0110 (поле, которое не читается расчётом, мертво) — только
направление было обратным: обещал носитель, которого нет.

**Факт третий: дыра была не в трёх плитках.** Проверка по всем 33:

| Семейство | Что есть на самом деле |
|---|---|
| terrain ×9 | `Tile.terrain` — объявленное поле dataclass |
| goods ×9 | `Good.id` — объявленное поле |
| фигуры ×3 | `Person.age_class` — объявленное поле |
| `architecture_bridge` | `Tile.bridge` — объявленное поле |
| 6 построек-жилищ | `Tile.dwelling` — **не объявлен** на dataclass, читается через `getattr` (2 места, `tile_view.py:432`) |
| `architecture_palisade`, `architecture_gate` | **ничего**: `seat`-формы описывают усадьбу, а не стену с проёмом |
| 3 keyed-плитки | **ничего**: они держат ветку `key → trim → resize → anchor` под проверкой |

## Решение

### 1. Два разных понятия, и оба объявлены

- **`data_carrier`** — поле симуляции, которое определяет изображённую сущность. Это
  **проверяемо** по коду, поэтому и проверяется.
- **`sprite_selector`** — поле, выбирающее, **какую именно** плитку рисовать. Их **нет**,
  и быть не может, пока `client/` заморожен. Объявлено один раз в `target`:
  `sprite_selector: none`.

Ни одно из этих понятий не значит «рантайм выбирает картинку». Первое — про опознание
сущности, второе — про выбор арта, и второго пока нет.

### 2. Два вида носителя, потому что проверяются они по-разному

| Вид | Что значит | Как проверяется |
|---|---|---|
| `declared_field` | настоящее поле dataclass в `ontology.py` | класс есть **и** поле объявлено в его теле |
| `optional_attribute` | существует в данных, но не объявлено | поле **читается через `getattr`** где-то в `sim/` |
| `none` | ничего не определяет | обязан сопровождаться `data_carrier_reason` |

Разделение обязательно. `Tile.dwelling` не объявлен на `Tile`, но читается в `tile_view.py`.
Назвать его `declared_field` — ложь, другой крайностью — пропустить его совсем — тоже ложь.

### 3. Пять проверок, у каждой есть мутация

1. У каждой плитки объявлен `data_carrier` — строкой или `null`.
2. У `null` обязательно есть `data_carrier_reason`.
3. Объявленный класс существует в `ontology.py`.
4. Вид носителя не врёт: `declared_field` объявлен, `optional_attribute` — нет, и
   читается через `getattr`.
5. `sprite_selector` равен `none` у всех 33 плиток.

Плюс две мутации на «тишину»: удаление одного объявления и удаление их всех с листа.

### 4. Молчание запрещено, отсутствие носителя — нет

Плитка без носителя законна: она может существовать ради геометрии или ради покрытия ветки
пайплайна. **Но молчание не законно** — молчание и есть то, чем референс тихо становится
ассетом. Отсутствие объявляется явно, с причиной.

## Альтернативы

- **Проставить трём keyed-плиткам `carrier: null` и больше ничего не делать.** Отброшено:
  это лечит симптом. Схема «носитель есть» сама по себе вводит в заблуждение, потому что
  читается как «рантайм выбирает по нему». Пока нет различения «данные» / «выбор картинки»,
  любая формулировка про носитель либо преувеличивает, либо пуста.
- **Оставить носители только у рисованных плиток, keyed считать вне схемы.** Отброшено:
  ровно на keyed-плитках и держится аргумент «это не ассет», а исключение их из схемы
  убирает аргумент из-под проверки.
- **Не проверять носители, объявить их вручную.** Отброшено: по правилу репозитория
  «нет проверки — нет результата». Несуществующее поле прошло бы ревью и всплыло бы в
  рантайме.
- **Проверять только `declared_field` и отбросить `Tile.dwelling`.** Отброшено: шесть
  построек-жилищ тогда окажутся без носителя, хотя носитель у них есть — просто optional.
  Это хуже, чем отсутствие честной пометки.
- **Заводить селектор спрайтов.** Отброшено: это работа `client/`, который заморожен, и
  решение Game Owner, а не art.

## Последствия

- `flat2d_proof_manifest.yml` публикует `data_carrier`, `data_carrier_kind` и
  `sprite_selector` у каждой из 33 плиток, плюс `target.sprite_selector: none` с причиной.
- `verify_proof.py` получил пять проверок носителей; у трёх из них проверка идёт в
  `sim/src/hillcourt/ontology.py`, то есть **за пределы art** — это сознательно, иначе
  обещание снова нечем проверить.
- `mutation_test.py`: 63 мутации вместо 56, из них семь новых на носители.
- Пять плиток честно помечены как не имеющие носителя: `architecture_cottage_plate`,
  `prop_flat_cart_empty`, `actor_villager_plate`, `architecture_palisade`,
  `architecture_gate`. Это не дефект, это факт.
- **Побочный эффект, о котором стоит сказать прямо:** верификатор теперь зависит от дерева
  `sim/`. Первый вариант искал онтологию подсчётом родителей от `__file__`, и в scratch-дереве
  mutation-теста находил пустоту — 31 ложное сбоя вместо одной честной ошибки. Теперь путь
  ищется по наличию файла, `HILLCOURT_REPO` передаётся явно, а если исходники не найдены,
  выдаётся **одно** сообщение вместо тридцати.

## Что запрещено следующим агентам

- Не писать, что рантайм «выбирает плитку» по какому-либо полю. Пока `client/` заморожен,
  селектора нет. Проверка это ловит.
- Не объявлять `data_carrier`, не проверив его по коду. Имя класса, имя поля и вид носителя
  проверяются автоматически, и выдуманное поле падает сразу.
- Не объявлять `declared_field` для поля, которое читается через `getattr`, и наоборот.
- Не оставлять плитку без `data_carrier`. Отсутствие носителя допустимо, отсутствие
  объявления — нет.
- Не считать `game_entities` носителем: он говорит, о ком плитка, а не о том, как она
  выбирается.
- Не убирать проверку носителей как «связанную с онтологией, не моё дело». Связь с
  `sim/` — единственное, что делает обещание проверяемым.
