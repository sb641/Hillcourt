# 0078. Честное время: часы пути, ETA по суткам, дневной контур Pack (Implementer)

Дата: 2026-09-24. Роль: Implementer. Исполнитель ADR 0069 (п. 2–3, п. 4 отдельно),
перекалибровка 0070 п. 1 и 0071 п. 3. Старые ADR не правятся. Зона: `sim/`.

## Контекст

Путь измерялся сутками: 1.0 «сутки» за поле и 8.0 за лес, а срок похода —
`ceil(дни/30)` месяцев. Два дня и два месяца выходили одинаково. ADR 0070
перекалибровал единицу (гекс ≈ 0.4 км), 0071 п. 3 задал якоря часов и срок по
суткам с дневным разрешением `Pack` (И-4 это разрешает: месяц остаётся основным
тиком, дневной контур — только для посылок в пути).

## Решение

### 1. Часы — единица пути

`engine/terrain.py`: `HOURS_PER_DAY = 24.0`, якоря `FIELD_HOURS` (нога 0.65,
конь 0.40, обоз 0.85, `arms` 0.8125 = нога ×1.25; водные — свой якорь),
`hours_scale(profile) = якорь / день_поля_профиля` и
`entry_hours(...) = entry_cost(...) × hours_scale(...)`.

Пропорции террейнов прежние (это и есть смысл формулы), поэтому Дейкстра не
тронут, порядок маршрутов не изменился, а фураж по дням остался честным.
Тропа ×0.9 / грунт ×0.8 / `road` как min — из `entry_cost`, без дублирования.
Вода без переправы — `IMPASSABLE` по-прежнему.

`find_path` возвращает `(route, hours)`; рядом `travel_days(hours)`
(сутки, `ceil(h/24)`, минимум 1) и `travel_hours(days)` (обратно). Месяцы
остались производной для логов: `travel_months(days)`.

### 2. `Pack.eta_date` с точностью до суток

`SimDate.advance_days/to_day_index` (месяц = 30 суток, как `DAYS_PER_MONTH`),
дробные сутки округляются вверх. `send_march`, `send_river_pack` и обоз пишут
`eta_date = date + travel_days`; логи приказа несут `travel_hours` (истина),
`days` (сутки) и `months` (производная) — месячный квант перестал быть
единственной истиной.

### 3. Дневной контур `Pack` (И-4)

Новая фаза `phase_day` после `phase_travel`: проходятся СУТКИ текущего месяца
(1..30), и для каждой `in_transit` посылки с `eta_date` внутри месяца
вызывается её штатный разбор (`hazards/travel.resolve_migrations/resolve_packs`,
`economy/caravan.resolve_caravans`) с датой прибытия. Ничего, кроме `Pack`, не
ходит по дням: месячный тик, дворы, экономика остались помесячными.

### 4. Пины переведены на измеренное, инварианты закреплены

- `test_march_path`: коридор обоза 4.25 ч, охотника 2.925 ч, приказ несёт
  `travel_hours` 1.3 и `days` 1; `eta_date.day != 1`.
- `test_caravan_module`/`test_caravan_trade`: фураж — в сутках, часы
  переводятся `hours_scale("caravan")` (фураж на часах — задача Economist).
- `test_caravan_report`: с ETA по суткам обоз с солью может уйти и разгрузиться
  В ТОТ ЖЕ месяц до `phase_inform` — тогда в деревне честно 0; пин «врёт» сохранён
  (при непустой деревне отчёт обязан быть > 0), исчез лишь ложный «должен быть
  ненулевой образец».
- `test_cycle_road_river_roi`: плот в часах быстрее сухих суток (3.74 ч против
  5.1 ч), в сутках разница пока не видна — вердикт зонда пересмотрен честно.
- Три сена/выпасных фикстуры: communal-доступ по ADR 0068/0077 дают только
  `works_tiles`/`common`, поэтому пастбище открывается правом, а не соседством.
- Новый `sim/tests/test_travel_hours.py` (20 тестов): якоря, пропорции, скидки,
  «100 гексов пешком = 2–3 суток», сутки/месяцы, `advance_days`, ETA с днём и
  приход похода в том же месяце, месяц остаётся основным тиком, детерминизм,
  дельта 0 + инварианты (дорога дешевит, но не до нуля; плот выигрывает только
  с водой на маршруте; лес обходится, если дешевле; сено до пашни; выпас 5–9
  ограничен).

4. Подгонять стартовые данные под старые числа (13/17/25).
