# 0063. Племя v1: объём по разведкам Legal/Economist (владелец)

Дата: 2026-09-24. Уточняет 0062 (старые не правятся). Закрывает объём v1 до кода по трём
разведкам: Legal (запрет ухода, оброк, вызов, отказ), Economist (числа оброка и вызова),
Systems (бюджет-гейт — ожидается).

## Контекст

- Legal: запрет ухода — обратный lookup `tribe_of_household → can_depart=False` (один
  guard в `phase_migrate`, без девятого пресета и без `Household.tribe_id`); смешанный
  оброк честно пишется **двумя `Obligation`**, а не расширением схемы; вызов племени —
  отдельное правовое действие, `send_sally` напрямую переиспользовать нельзя (ложная
  модель «двор барона выехал»); событие отказа/мятежа — высокая цена, в v1 декларативно.
- Economist: в каноне серебра почти нет → денежный оброк в v1 = «оброк из пустого амбара»,
  то есть ложь; натуральный оброк `0.6 зерна/мес на двор` (как сокмен) честен и умеет
  уходить в `arrears`; `muster_profile` без новых товаров = «сколько взрослых и комплектов»,
  всадник = конь + комплект; `loyalty` не участвует в `hunger`/`labor_days`.

## Решение

**v1 (код):**
1. `Tribe` — данные и право по 0062 (стойки, `law_profile_id`, `chief_person_id`,
   `tribute_terms`, `muster_profile`, `loyalty`, `granted_land`), грузятся из YAML.
2. **Запрет ухода:** lookup по составу племени в `phase_migrate` → `can_depart=False`;
   при `annexed` членство снимается, дворы живут обычной механикой.
3. **Оброк v1 — только натуральный:** `Obligation(kind=levy, basis=fixed, due_good=grain,
   due_amount=0.6, period_months=1)` на каждый племенный двор, платится только при
   `allied|vassal`, идёт в амбар корня, неоплата → `arrears` (механика уже честна).
   Денежная примесь — только если у племени фактически есть серебро; **не в v1**.
4. **Вызов v1 — проверка «может дать», не действие:** `muster_profile` = данные +
   проверка «есть взрослые + комплект(ы) (всадник — конь)»; нового вызова/handler в v1 нет
   (ADR 0062 v2), `war_kit` тэна не переиспользуется как норма племени.
5. **`loyalty` в v1 — только чтение:** не влияет на голод, труд, выбор действий, окна;
   падает лишь по событиям v2. Число в мире, но не факт для игрока (виден только через
   `Report` — И-3).

**v2 (отдельный ADR, не сейчас):** дипломатия (переходы стойки), действие вызова
(call-obligation), отказ/мятеж и подавление, денежный/смешанный оброк, `Community`-титул.

## Альтернативы

- Смешанный оброк одной схемой — отклонено (Legal: `Obligation` однопредметный; две
  `Obligation` честнее, новая схема — цена без нужды в v1).
- Переиспользовать `send_sally` — отклонено (ложная модель исполнителя).
- Девятый пресет `tribe` — отклонено (личный статус ≠ коллективный субъект; смешает оси).
- Денежный оброк сразу — отклонено (серебра нет: оброк из пустого = ложь, И-9).

## Последствия

- Экономика v1 не трогает канон: оброк 0.6/двор/мес — малая доля, окна §1 держатся;
  дельта 0. Числа-кандидаты — таблица Economist, проверка — стенд Table.
- Новая сущность `Tribe` правит онтологию через Scribe по этому ADR.
- Критерий v1: племя грузится из YAML; уход племенных дворов не срабатывает; оброк
  платится/уходит в `arrears` только у `allied|vassal`; проверка «может дать вызов»
  честна (нет взрослых/комплектов → не может); `loyalty` не влияет на числа.

## Что запрещено следующим агентам

1. Переиспользовать `send_sally` как племенной вызов.
2. Расширять схему `Obligation` под смесь в v1 (две повинности — закон).
3. Вводить девятый пресет или `Household.tribe_id` без доказанной нужды.
4. Денежный оброк в v1 при отсутствии серебра у племени.
5. Связывать `loyalty` с `hunger`/`labor_days`/окнами.
