# 0082. Служба 60–90 суток и племенной вызов

Дата: 2026-09-24. Исполняет решения владельца по ADR 0066; старые ADR не правятся.

## Контекст

Месячная служба тэна и проверка потенциала племени не выражают длинный поход. Нужен общий правовой контур без новой мировой сущности: повинность `muster` на 2 или 3 месяца, два рейса Pack и честное различение неприбытия, невозможности и отказа.

## Решение

1. `Obligation(kind="muster")` использует `period_months=2/3`; дедлайн вычисляется от `Pack.departed_date`, а `service_bad_months` не становится календарём экспедиции. Число необходимых голов хранится в существующем `due_amount` с единицей измерения в правовом вызове.
2. На повинность создаётся outbound Pack и отдельный return Pack. Минимальная связь — `Pack.obligation_id`; новых сущностей нет. Фактически вышедшие люди содержатся в `member_ids`, Pack создаётся только при непустом составе.
3. `call_status` получает `in_service`, `returned`, `overdue`; `refused` ставится только отдельным действием решения племени, `unable` — при нехватке людей/комплектов/корма или потере Pack. `Pack.lost`, тишина и отсутствие Pack не означают `refused`.
4. Тэна и союзное племя вызываются разными правыми входами: тэн получает повинность своего книжного двора, племя — по одной повинности на каждый двор поселения. `send_sally` и норма `war_kit` тэна не переиспользуются.
5. Во время похода `Manor` остаётся владельцем земли и книгой; регент не создаётся. Подавление тэна использует существующий `revoke_thegn`. `annexed`/`chief_person_id` для племени остаются вне v1.
6. Новые поля: только `Obligation.call_status` и `Pack.obligation_id`; других полей и сущностей нет. `world.py` и `state_hash` не меняются в этой сдаче; их покрытие — обязательный follow-up Implementer-3 после freeze.
7. Каталоги не получают новых товаров, рецептов или прав: `muster` — вид повинности, а не материальный объект. Новые id не нужны. Числа канонов не меняются; хеши миров со службой считаются открытым сдвигом до follow-up покрытия state hash.

## Альтернативы

- Новый `ServiceCall` — отклонено: достаточно существующих `Obligation` и `Pack`.
- `Pack.status=refused` — отклонено: при отказе Pack может не существовать.
- Переиспользовать `send_sally`/`war_kit` — отклонено: другой исполнитель и другое правовое основание.
- Новый регент или `Manor` для отсутствующего барона — отклонено: владелец книги не меняется.

## Последствия

- Зона: `sim/src/hillcourt/legal/`, минимальные поля `sim/src/hillcourt/ontology.py`, профильные тесты и каталоги при необходимости.
- Проверяются: срок 2/3 месяца, возврат в срок, overdue, lost, тишина, refused/unable и `revoke_thegn`.
- Профильный прогон: `test_muster_service` + `test_thegn_service` — 24/24 OK. Полный прогон на текущем параллельном дереве: 625 тестов, 27 FAILED и 2 ERROR в чужых caravan/scenario/economy/water зонах; Legal-профили зелёные, чужие ошибки не чинятся.
- `state_hash` не читает новые поля; после freeze Implementer-3 должен добавить их покрытие отдельным изменением и повторно объявить хеши.
- Материя не создаётся; Pack и повинности меняют право и состояние, не запасы.

## Что запрещено следующим агентам

1. Выводить `refused` из отсутствия Pack, `Pack.lost` или тишины.
2. Использовать `service_bad_months` как срок похода.
3. Создавать Pack без фактически вышедших людей или смешивать outbound/return.
4. Вводить регента, `annexed`/`chief_person_id` для племени без политического ADR.
5. Править `world.py`, `engine/`, `economy/`, `scenario.py` в этой сдаче.

## Проверка

```bash
PYTHONPATH=sim/src python3 -m unittest sim.tests.test_muster_service sim.tests.test_thegn_service -v
bash sim/run_tests.sh
```

Критерий: повинность имеет 2/3 месяца и корректный дедлайн; два Pack связаны с повинностью; возврат вовремя даёт `returned`; просрочка даёт `overdue`; потеря/тишина не дают `refused`; активная команда даёт `refused`; `revoke_thegn` не меняет семантику подавления. Дельта материи 0.
