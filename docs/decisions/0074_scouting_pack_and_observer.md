# 0074. Разведка: `purpose`/`profile_id`, правила наблюдения, честный свидетель (владелец)

Дата: 2026-09-24. По проекту Systems (цикл 52) для ADR 0073. Правит онтологию `Pack`
и семантику `Report`; код — после приёмки текущего среза.

## Контекст

Хозяин: отшельника/хижину можно найти только если кто-то прошёл рядом; вышка/охотник/
лесничий замечают разное; игрок не всеведущ. Systems: движение уже есть (`Pack.kind=party`,
маршрут, ETA), знание строится из доставленных `Report`; не хватает смысла «зачем идёт» и
наблюдения как результата. Текущий `Report.observer_id` всегда `"player"` — это ложь: мир
не наблюдал, наблюдала партия.

## Решение

1. **Минимум полей, ноль сущностей:** `Pack.purpose` (сейчас: `scout`; обычные `send_party`/
   `send_march` — обычное значение) и `Pack.profile_id` (`hunters`, `forester`, `party`,
   позже `tower`). Наблюдатель не хранится отдельно — источник и так `Pack`.
2. **Правила наблюдения:** на **том же гексе** — факт без броска (партия физически встретила);
   на 1 гекс — вероятность по профилю и покрову (поле/луг слабое укрытие, лес сильное, топь
   сильное; `Hazard` ухудшает); на 2 гекса — сигнал (дым/след/костёр) с `confidence≈0.5`
   и пометкой «слух»; **дальше двух гексов — никогда**. Без `Pack` в гексе наблюдения нет:
   месячный тик сам по себе не открывает ничего.
3. **Потоки случайности:** бросок наблюдения — именованный физический поток (`rng_world`),
   формулировка/шум вести — `rng_news`. Дедерминизм обязателен.
4. **Честный свидетель:** `Report.observer_id` = наблюдатель (`Pack`/партия/человек), а не
   строка `"player"`; `source` различает разведку и гонца, а не маскирует обоих под `messenger`.
   Гекс становится известным только из доставленной вести (И-3) — тест обязан падать, если
   код расширит `known_tiles` без отчёта.
5. **Вышка/башня — не в v1:** наблюдение вне `Pack` (статический источник) требует отдельного
   ADR; сейчас дозор = партия на месте ( ADR 0070: гекс колонны, позже v2).
6. **Партия не видит «вглубь»:** наблюдение ограничено гексами маршрута и кольцом 1–2 гекса
   вокруг места нахождения; дальние клетки в отчёт не попадают.

## Альтернативы

- Случайные события от тика — отклонено (всеведение, дешёвый шум).
- Новая сущность `Scout`/`Watcher` — отклонено: `Pack` уже несёт всё нужное.
- `observer_id="player"` как сейчас — отклонено: ложь в метаданных вести (И-3 по духу).

## Последствия

- Реализация: Implementer (`purpose`/`profile_id`, правила наблюдения в `phase_travel`/
  `resolve_packs`, дедуп), Info (канал разведки, честный `observer_id`, «слух» на 2 гексах),
  Scribe (`03`/`05`), Economist — не трогается.
- Находка (отшельник/хижина) — обычное поселение в 1 двор; условия появления и цена — проект
  World/Systems, затем ADR.
- Каноны не сдвигаются (знание не трогает экономику напрямую).

## Что запрещено

1. Открывать гекс без доставленной вести.
2. Наблюдать дальше 2 гексов или без `Pack` в гексе.
3. Оставлять `"player"` наблюдателем при разведке.
4. Вводить башню-дозор без отдельного ADR.

## Проверка

```bash
bash sim/run_tests.sh
```

Критерий: сюит зелёный; тест — партия в лесу замечает, в поле реже; в 2 гексах только
слух; в 3+ — тишина; без `Pack` — ноль наблюдений; `observer_id` = партия; `known_tiles`
растёт только из вестей; дельта 0.
