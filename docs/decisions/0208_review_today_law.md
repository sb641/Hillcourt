# 0208. Адверсариальная проверка сегодняшнего закона (ADR 0199–0206, мир после ADR 0207)

## Назначение

Отчёт Critic о шести новых законах и о пересобранном баронстве, **до** того как Scribe
впишет их в документы. Critic не автор проверяемого кода и не дорабатывает его: в дерево
за этот заход не внесено ни одной правки кода, каталога или сценария (проверено `diff -q`
против побайтной копии, §Границы). Всё, что ниже, — измерение и воспроизводимые команды.

Инварианты, по которым идёт ревизия, названы ниже поимённо **и по адресу**
(ADR 0191): **И-1** — `docs/00_constitution.md:10-17`, **И-3** — `docs/00_constitution.md:24-27`,
**И-9** — `docs/00_constitution.md:51-53`.

Итог одной строкой: **законы в силе — 0199, 0200, 0201 (ядро), 0202, 0203, 0204, 0205
(M1–M4), 0206 (ставка и приказ); не в силе — пять позиций из списка в конце отчёта.**

   `test_no_cap_and_the_tile_keeps_every_increment` и `test_harvest_never_drains_the_crop`.
   **Заявление ADR 0200 подтверждено дословно.** Прирост идёт в

4. **Оброк — ровно доля, двойного счёта нет.** ADR 0206 разрешил игроку назначить ставку,

   | 0.0 | 0.000 | 164.750 | 0.000 | 0.0 |

   | 0.5 | 86.725 | 173.450 | **0.500** | 0.5 |

   | 1.0 | 175.100 | 175.100 | **1.000** | 1.0 |

   урожая двора** — даже при `1.0` берётся ровно всё, не больше.

### 2. НАХОДКА 1 — повинность начисляется дважды в месяц (серьёзно)

**Что.** В новом баронстве у **20 дворов из 150** `Household.obligation_ids` содержит
**один и тот же id дважды**. Для двора `hh_hill_sokeman_001` это повинность **оброка**.

**Где.**

- `sim/src/hillcourt/scenario.py:1203` — `_apply_declared_holdings(...)`, который идёт
  приказом `grant_tenure` (`actions.py:436` → `materialize_obligations`).
- `sim/src/hillcourt/scenario.py:1205-1206` — `materialize_obligations` вызывается
  **второй раз, для всех дворов, безусловно** (без `_clear_obligations`, без проверки
  «уже заведено»).
- `sim/src/hillcourt/legal/bundles.py:68` и `:85` — `household.obligation_ids.append(...)`
  **безусловно**, в обоих конструкторах (`_duty` и `_rent`).
- `sim/src/hillcourt/engine/tick.py:386` — `for oid in sorted(household.obligation_ids):`
  обходит **список**, а не множество, поэтому одна и та же повинность проходит фазу
  `phase_obligations` **дважды за месяц**.

**Как воспроизвести.**

```bash

```


**Минимальный контрпример — оброк, а не барщина.** Двор `hh_hill_sokeman_001`,
`obl_hh_hill_sokeman_001_fixed_rent_grain_or_pence`, `due_amount = 0.6`:

| месяц | `arrears` | `arrears_days` | должно быть при due=0.6 |
|---|---|---|---|
| m01 | **1.200** | **2** | 0.6 / 1 |
| m02 | **2.400** | **4** | 1.2 / 2 |
| m03+ | 2.400 | 4 | +0.6/мес |

Двору предъявлен **двойной оброк**, и `arrears_days` растёт на **2 за месяц**.

**Почему это нарушение.** Не И-1 (материя здесь не создаётся) и не бухгалтерия. Это
нарушение закона «одна повинность — одно начисление в месяц» (`legal/obligations.py`,
`docs/09_law_and_land.md`) и прямого запрета ADR 0136/0131: барщина — сезонная, из
`seasonal_labor_days`, и 8 трудодней в месяц удваивать нечем. `arrears_days` при этом —
не счётчик: он же кормит весть шерифа (`info/briefing.py:228-233`, «дворов с недоимкой
N»), то есть **игрок получает ложную весть** о числе должников. И это ровно тот вопрос,
который задал стол плейтеста: «оброк нельзя собрать дважды за один месяц».

**Чего я НЕ утверждаю.** Двойной **перевод зерна** по повинности доли (`basis: share`)
на данных сегодняшнего баронства **не происходит**: удвоен только `seasonal_labor`
(барщина), а `obl_*_rent` у 20 городских дворов одиночны. Но путь один и тот же —
`_rent` (`bundles.py:85`) добавляет id тем же безусловным `append`, так что одна правка
данных (сокмен с объявленным наделом) включает двойной сбор оброка. Называю это как
**одну строку от взрыва**, а не как сегодняшний ущерб.

**Кому.** `scenario.py` — зона Implementer, `bundles.py` — зона Legal. Правка тривиальна
(снимать `append` при повторе или чистить перед `materialize_obligations`), но **не моя**.

### 3. НАХОДКА 2 — весть «Холм» называет столицу, а читает один гекс (серьёзно)

**Что.** `subject_kind="manor"` (ADR 0205) — **чист**, проверил отдельно и первым, как
просил хозяин. А вот весть о холме в **новом мире** врёт по имени своему предмету: текст
обещает «Холм», то есть столицу поселения, а число — сумма зерна дворов **одного гекса**.

**Где.** `sim/src/hillcourt/info/briefing.py:34-36` (`_court_tile` — это coord поселения,
то есть гекс столицы), `:61-66` (`_grain_on_tile` — сумма по `_live_households_on_tile`),
`:93-105` (текст `f"Холм: во дворах зерна около …"`, `subject_id = court_tile`).

**Как воспроизвести.**

```bash
PYTHONPATH=sim/src python3 -c "
from pathlib import Path; from collections import Counter
from hillcourt.scenario import load_scenario; from hillcourt.engine.seat import court_tile_id
for n in ['start_stand','v0_hill_and_salt','v0_barony_100']:
    w=load_scenario(Path(f'design/scenarios/{n}.yml'), seed=1729)
    c=court_tile_id(w); s=w.settlements[w.player.court_settlement_id]
    live=[h for h in s.household_ids if w.households[h].left_at is None]
    on=[h for h in live if w.households[h].current_tile_id==c]
    g=lambda hs: sum(w.get_stock(w.households[h].stock_id).amounts.get('grain',0) for h in hs)
    print(f'{n:16s} дворов в поселении={len(live):3d} на гексе зала={len(on):3d} '
          f'зерно гекса={g(on):7.1f} зерно поселения={g(live):7.1f} покрытие={100*g(on)/g(live):5.1f}%')"
```

```
start_stand        дворов в поселении=  2, на гексе зала=  2 | 140.0 |  140.0 | 100.0%
v0_hill_and_salt   дворов в поселении=  2, на гексе зала=  2 | 140.0 |  140.0 | 100.0%
v0_barony_100      дворов в поселении= 90, на гексе зала= 12 | 122.4 |  918.0 |  13.3%
```

**Минимальный контрпример.** На `v0_barony_100` (целевой мир ADR 0207) в `hill_court`
живут **90 дворов**, на гексе стола `t_45_50` — **12**. Весть «Холм: во дворах зерна около
N» при `confidence=1.0, noise=0.0, distorted=False` показывает **13.3 %** столицы.
Игрок читает «мой холм умирает», имея 918.0 зерна на 90 дворов.

**Почему это нарушение.** ADR 0205 §Решение формулирует закон словами «**весть обязана
называть то же, что читает**» и в §«Что запрещено» повторяет: «Весть, которая называет не
то, что читает». Это **тот же класс дефекта**, который ADR 0205 создавался, чтобы убить
(тогда «Холм» называл личный ларёк лорда) — просто на баронстве гекс зала отстал от
поселения в 7.5 раза, и подмена повторилась. И-3 при этом **не нарушено** (утечки
чужой истины нет, см. §4), но закон ADR 0205 нарушен.

**Почему это не поймали — и это отдельная находка, см. §5 (НАХОДКА 3).** ADR 0205 проверяет
предмет только на `start_stand` и `v0_hill_and_salt`, где поселение **и есть** гекс
(2 двора из 2). На них «читать гекс» и «читать поселение» — одно и то же число.

### 4. НАХОДКА 3 — весть о книге корня (проверено первым, чисто)

Хозяин просил смотреть сюда внимательнее всего. Результат: **закона не нарушено**, и
вот чем это доказано, а не на слово.

- **Предмет вести — тот самый адресат.** `briefing.py:127-133` читает
  `manor_stock(world, root_manor(world))` = `Manor.stock_id`. Проверил потоки по
  `settlement:hill_court` (= `manor_hill.stock_id` в баронстве) за 8 месяцев
  `start_stand`:

  ```
  ВТЕКАЕТ: harvest_grain 393.50, hunt 8.00, caravan_unload 4.80
  ВЫТЕКАЕТ: relief 167.72, board 140.76, caravan_load 35.00, feed 18.40, cart_wear 0.10
  остаток: 599.43   весть: «Книга сеньора: в амбаре зерна около 599» → barn_grain=599.4
  ```

  Это ровно тот сток, из которого берут `grant_grain` и `relief`, как ADR 0205 и обещал.
  Текст «столько есть на раздачу» — **истинен**.

- **Всеведение не открыто.** `facts={"barn_grain": <float>}` (`briefing.py:140`) — плоское
  число. `build_player_view` (`news/views.py:68-78`) и `build_player_knowledge`
  (`info/knowledge.py:76-83`) читают только `delivered_reports`. И-3 держится: в представлении

- **Достоверность 1.0 законна** — свидетель сам держатель, задержка 0, шум 0
  (`docs/05_information.md:70`). Условие «предмет = свой запас» выполнено: см. выше.
- **Оговорка, которую стоит записать, но она не дефект.** `Manor.stock_id` и
  `court.stores_stock_id` совпадают (`settlement:hill_court`) — ADR 0205 сам это
  признаёт в «Альтернативах». То есть «книга сеньора» физически есть **общинный амбар
  столицы**, в который течёт вся оброчная рента и из которого идёт подача. Называть это
  «книгой сеньора» можно (он им распоряжается), но Scribe должен написать, что это
  **общественный амбар в книге**, иначе игрок прочитает «моё» там, где «наше».

### 6. НАХОДКА 5 — сторож, который должен был ловить мёртвые поля, слеп (Блок 5)

**Что.** `TestCatalogFieldHasAReader` (`sim/tests/test_docs_claims.py:1246-1264`) определяет
«поле без читателя» **текстовым поиском имени** по всему блобу `sim/src/hillcourt/**/*.py`:

```python
if not re.search(rf"\b{re.escape(field)}\b", blob):
    out.add((cls, field))
```

`LegalStatus.court` от такого поиска **спасается чужими совпадениями**: имя `court`
встречается в блобе **22 раза** (`court = world.settlements.get(world.player.court_settlement_id)`
и т. п.), поэтому поле классифицировано как «имеющее читателя» и **никогда не попадает
в `ZERO_READ_ALLOWLIST`** — то есть четыре мёртвых поля, а не три, а список об этом не знает.

**Как воспроизвести.**

```bash
cd sim/src/hillcourt && python3 -c "
import re,pathlib
blob='\n'.join(p.read_text() for p in sorted(pathlib.Path('.').rglob('*.py')) if p.name not in ('ontology.py','catalogs.py'))
for f in ['court','marriage_needs_permission','inheritance','can_sell_land']:
    print(f, '-> сторож считает мёртвым:', not re.search(rf'\b{f}\b', blob))"
```

→ `court -> False` (сторож слеп), остальные три → `True`.

**Почему это нарушение.** Сторож заявляет: «у каждого поля каталожного `dataclass` есть
читатель **вне** `ontology.py` и вне `catalogs.py`». Он проверяет не чтение поля, а
**совпадение подстроки**. Любое будущее поле, имя которого совпадёт с именем переменной
где угодно в дереве, получит бесплатный пропуск. Сторож ADR 0155, который сам списан с
«тест зелёный, потому что он ничего не проверяет», проверяет ровно это.

### 8. Рычаг «сколько платить» — обещание исполнено (Блок 4, положительный результат)

`docs/01_player_fantasy.md:7` («кому держать землю, **сколько платить**, кого послать
за соль») обещал рычаг; `:12` называет его среди рычагов игрока. ADR 0206 его дал, и он
честен:

- `rent_amount_for` (`obligations.py:226-253`) считает `ставка × урожай`, `round(..., 3)`;
- `rent_rate_for` (`obligations.py:201-223`) берёт **право**, а не каталог;
- линейность проверена замером в §1: 0.9 даёт **ровно девять** счётов 0.1;
- **выкрутить себе в убыток нельзя**: ставка ограничена `[0,1]`, а при `1.0` лорд берёт
  максимум; `0.0` — честный выход («оброк не заводится»), а не обман;
- **оброк с урожая, которого нет, взять нельзя**: база — проводки `harvest_grain`
  прошлого месяца, а сбор сверяется с остатком стока
  (`tick.py:415-417`, `available + EPSILON >= due`).

Заодно: `runner.py:537-560` теперь читает applied-ставку **из права**, а не из каталога,
и `rent_share_is_switch_only` снята — заявка Implementer'у из ADR 0206 §Отменено **выполнена**.
