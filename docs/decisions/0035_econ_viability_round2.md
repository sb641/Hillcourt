# 0035. Viability-раунд 2: очередь E1–E8 без подъёма yield (Economist)

## Контекст

Game Director поставил Economist очередь жизнеспособности: E1 сено/тягло → E3
бревно → E2 лемех → E4 скот/обмен → E6 wasted → E7 цены → E8 смертность; роды —
отдельно ADR 0031. Часть уже в коде (`economy/{labor,exchange,demography,manor}.py`,
`needs.yml`, `actions_household.yml`). Сюит красный по демографии (окна живых
two/shire, соль two — см. ADR 0032/0033); красные тесты — не повод поднимать yield.
Окна чисел — `TBD`, их впишет Economist после замеров.

## Решение

Без подъёма yield (`seasons.yml`, `TOOL_YIELD_FACTORS` не тронуты):

1. **E1, сено/тягло.** Косьба `gather_draft_hay` (рецепт, труд из остатка, кап
   клетки общий); корм скота — сено своего стока (`needs.yml:livestock`);
   выгода тягла — только через труд партии (`draft_plough_factor`), не зерном
   с неба. Гейт: косьба после барщины, добор только при нехватке.
2. **E3, бревно в обороте.** Покупка `buy_log` в `exchange.py`: цена
   `LOG_PRICE_GRAIN = 0.5`, кап `TRADE_LOG_MAX = 4.0`, всё — `transfer`.
   Гейты: у покупателя `log < 1.0` и `food_months ≥ 1.0`; у продавца `log ≥ 4.0`.
3. **E2, лемех достижим.** Очередь `idle_repair` (`actions_household.yml`):
   `repair_axe → smelt_iron_bloom → smith_iron_share → smith_kit`; рецепт
   `smelt_iron_bloom` закрывает И-7 для крицы. Гейт: лемех — трудом и очередью,
   не выдачей; бонус выхода держится `grant_tool`/`tool_yield_factor`.
4. **E4, скот/обмен.** Покупка `buy_beast` в `exchange.py`: вол 8.0, осёл 5.0,
   конь 12.0 зерном; разведение/созревание `breed_*/mature_*` в `tend_animals`
   (`livestock.py`). Гейты: `food_months ≥ 1.0`; продавец держит пару
   (остаток `≥ 3.0`); конь — только свободному (`can_hold_horse`).
5. **E6, wasted вместо молчаливого недобора.** `_render_pool(caps)`: барщина
   списывается не выше спроса манора; излишек остаётся двору на свой надел.
   Гейт: кап по `demesne_labor_demand_this_month`; дни без доменных клеток —
   в `wasted_labor_days`, а не в урожай.
6. **E7, цены — каталог, не рынок.** Фикс-цены: бревно 0.5 зерном, скот таблицей
   E4, свинья 3.0 серебром, зерно 0.5 серебром. Гейт: цен нет в `barter_memory`
   (там только доля доехавшего груза); обмен — только `transfer` на своей клетке.
7. **E8, смертность.** `_die_by_age` (`demography.py`) + `needs.yml:death`
   (ребёнок/взрослый/старик + надбавка за старостью). Гейты: ставки низкие,
   баланс держат роды; люди — не материя (Ledger не трогаем); жребий —
   `rng.economy`, порядок по `id`.

## Альтернативы

- **Поднять yield/ускорить созревание/смягчить пороги родов ради окон** —
  отклонено: ломает равновесие §3 столового счёта («оба жирные» / деморай);
  окна правит только ADR автора с замерами.
- **Рынок с плавающими ценами** — отклонено: в v0 цены — труд × ставка найма,
  фиксированы; рынок — новая система без сущностей.
- **Лемех выдачей всем / скот появлением** — отклонено: нарушает И-1/И-7
  (материя из ничего, объект без рецепта/появления).
- **Списывать барщину сверх спроса** — отклонено: прячет недобор и режет надел;
  вместо этого `wasted_labor_days` виден в логе.

## Последствия

- Канон замерен (Economist, 36/60 мес): hill живых 12, голод 31; two живых 16,
  голод 299; shire живых 26, голод 525; соль 15.6 и дельта 0 везде. Сдвиг two
  18→16 — рты демографии (оформлено здесь, не молча).
- Тесты: `test_demography` (роды + смертность), обмен (`logs_bought`,
  `beasts_bought`), кузня (след `iron_bloom`), `wasted_labor_days` при пуле
  без клеток; `test_matter_conservation` зелёный.
- Долги за Game Designer: стартовые наборы сценария (сено/пары/брёвна),
  `phase_hay` как единственная косьба (убрать второй вызов из `livestock_month`).

## Что запрещено следующим агентам

1. Поднимать yield, смягчать роды или ускорять созревание без нового ADR с окнами.
2. Вводить рынок/плавающие цены без сущностей и ADR.
3. Создавать материю: только `transfer`/рецепт/`external_in`, дельта 0.
4. Класть новое тягловое стадо без проверки рерола `rng.economy` (трио).
5. Чинить чужие зоны столом: косьба/сценарии — Game Designer, пороги — Economist
   предложением.

материи 0; `births > 0`, `deaths ≥ 0`, живых hill ≥ 11, two ≥ 16, shire ≥ 24;
`logs_bought ≥ 1.0`; `beasts_bought` — механизм доказан скриптом (1.0), в каноне
0 до скормленных наборов; окна two/shire меняет только ADR автора демографии.
