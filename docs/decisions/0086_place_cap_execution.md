# 0086. Исполнение: механический кап urban 20 (Implementer)

Дата: 2026-09-24. Роль: Implementer. Исполнен ADR 0083 в `engine/tile_view.py` и
`sim/tests/`. Старые ADR не правятся.

## Назначение

Сельский гекс и городской квартал должны иметь разные механические пределы: 5 и 20
жилых дворов. Городской кап не должен обходиться данными сценария, а 40 дворов на
гекс не вводится.

## Правила

1. `tile_max_households` возвращает 20 для гекса с маркером `urban`, иначе 5.
2. `can_settle` использует этот кап вместе с проверкой пригодности ADR 0080.
3. Маркер остаётся данными `marks`; новых полей онтологии и сущностей нет.
4. Явный тестовый `Tile.max_households` hook сохранён для гонки посадок; новый
   пользовательский лимит 40 не создаётся.

## Проверка

```bash
PYTHONPATH=sim/src python3 -m unittest sim.tests.test_place_cap sim.tests.test_tile_view -v
bash sim/run_tests.sh
```

Тесты проверяют сельский cap 5, urban cap 20, приём 20 и отказ 21-го двоя, а также
старый сельский отказ и детерминизм. Полный сюит: `Ran 642 tests ... OK`; дельта 0.

## Альтернативы

- Оставить один cap 5 отклонено: urban-гекс не может вместить 20 дворов.
- Ввести 40 отклонено: для этого нужен отдельный ADR с измерением пригородов.
- Переносить cap из `tile_view.py` отклонено: это отдельный рефакторинг зон.

## Последствия

Городские кварталы получили честный предел 20; сельские гексы остались на 5.
Миграция и городской путь соли изменились вместе с ADR 0080, что отражено в
перемеренном пине 6.0; окна §1 не менялись.

## Что запрещено следующим агентам

1. Обходить cap раскладкой или параметром загрузчика.
2. Вводить 40 дворов на гекс без нового ADR.
3. Считать плотность только видовым форматированием.
4. Переносить `can_settle`/`tile_max_households` из `tile_view.py` без отдельной задачи.
