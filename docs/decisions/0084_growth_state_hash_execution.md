# 0084. Исполнение: индекс роста и полнота `state_hash` (Implementer)

Дата: 2026-09-24. Роль: Implementer. Зона: `engine/`, `world.py`, `sim/tests/`.
Исполнены два follow-up Critic к lazy LOD и состоянию мира; старые ADR не правятся.

## Назначение

Подключить уже существующий детальный рост к тику и перестать терять новые поля
повинности/посылки при вычислении `state_hash`. Два мира с разной службой или
разной связью Pack с повинностью должны иметь разные хеши.

## Правила

1. `phase_growth` вызывает `run_detailed_growth(world, season_factor(month))`; обходятся
   только `World.growth_tile_ids` — поселения и их `works_tiles`.
2. Внешний приход остаётся только через `Ledger.external_in` с `rule_id`; coarse-лес,
   не входящий в индекс, не растёт.
3. `state_hash` включает `Obligation.call_status` и `Pack.obligation_id`; старый набор
   полей и детерминированный порядок обхода не меняются.
4. Новых мировых сущностей и полей нет; hash-поля уже существуют в онтологии.

## Проверка

```bash
PYTHONPATH=sim/src python3 -m unittest sim.tests.test_barony_100.TestLazyGrowth sim.tests.test_state_hash_followup -v
bash sim/run_tests.sh
```

`test_barony_100` на 10 000 гексах проверяет индекс, рост settlement/works_tiles,
отсутствие роста coarse-леса, равенство числа обращений к стокам и линейный замер.
`test_state_hash_followup` проверяет различие хешей и повторяемость. Финальный сюит:
`Ran 642 tests ... OK`.

## Альтернативы

- Оставить полный обход `world.tiles` в `phase_growth` отклонён: 10 000 гексов не должны
  платить за coarse-деревья.
- Хешировать только дату и суммы отклонены: статус службы и обязательство — часть мира.

## Последствия

Прирост материи теперь действительно тикает на детальных гексах; внешний поток и
`state_hash` полнее отражают состояние. Детальные каноны и дельта проверяются ниже.

## Что запрещено следующим агентам

1. Обходить все `world.tiles` в `phase_growth`.
2. Создавать материю без `external_in`/`rule_id`.
3. Исключать `call_status` или `obligation_id` из `state_hash`.
4. Добавлять мировые поля ради этого follow-up.
