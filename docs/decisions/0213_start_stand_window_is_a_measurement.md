# 0213. Окно `start_stand` объявляется замером: старое окно не было измерением

## Назначение

`design/scenarios/ACCEPTANCE.md` §1 объявлял окно стенда `start_stand` числами
«соль 20.0, зерно 148.7, рента 13.8». Окно — измерительная база приёмки, и §5 того же
файла прямо запрещает подгонять его под прогон. Здесь объявляется **новое** окно,
снятое командой, и объясняется, чем было старое: **оно не было измерением.** Старое
окно не стирается, а остаётся в файле историей с пометкой.

Правка не трогает ни кода, ни каталогов, ни чисел экономики. Это запись Scribe: она
меняет только текст приёмки.

## Правила

1. Окно приёмки — **диапазон плюс команда его получения**. Число без команды — мнение
   (ADR 0190, ADR 0191).
2. Смена окна — **новый ADR**, а не прогон и не правка строки в `ACCEPTANCE.md`
   (§5 `ACCEPTANCE.md`).
3. Число, которое не воспроизводится, **помечается как не измерение и остаётся в файле**
   с происхождением, а не удаляется.
4. Снимок ревизии (хеш, отпечаток файла) **не окно**: он двигается, и его сдвиг —
   не повод переписывать окно.

## Контекст

### Откуда взялись «148.7 / 13.8 / 20.0»

Числа «148.7 зерна», «13.8 рента», «21.2 соли», «362-365 голодных дворомесяцев»
встречаются в репозитории ровно в двух местах, и оба — не замер:

- `design/review/critic_canon_0143_0148.md:282` — строка таблицы «Число | Где заявлено |
  Статус», где в колонке «Где заявлено» стоит **«задание»**;
- `design/review/critic_canon_0149_0153.md:97` — та же строка, перенесённая дальше по
  реестру, с вердиктом «**НЕ ТРЕБОВАЛА**»: «Ни одного из этих чисел нет в 0143–0148. В
  0149–0153 их тоже нет (grep)».

То есть это был **список чисел, которые Critic положено проверить**, а не результат
проверки. Проверявший их не проверил, список не воспроизвёлся ни в одном ADR, и числа
попали в окно приёмки как «измерительная база». Соль `20.0` — единственное из трёх, что
хоть как-то совпадает с деревом: это соль в замке на 1-м и 2-м месяцах стенда
(§Замер, помесячный прогон), но не на 24-м, как объявляло окно.

### Проверка «а может, окно всё-таки верное, просто на другом горизонте или сиде»

Горизонты 12 и 24 месяца, сиды 1729 и 4242, плюс «без `--seed`» (сид сценария 1729):

| прогон | зерно | соль | рента |
|---|---|---|---|
| 12 мес, 1729 | 790.7 | 29.6 | 26.8 |
| 12 мес, 4242 | 788.9 | 29.6 | 25.2 |
| 24 мес, 1729 | **1248.0** | **39.2** | **74.3** |
| 24 мес, 4242 | 1232.2 | 39.2 | 70.0 |
| 24 мес, сид сценария | 1248.0 | 39.2 | 74.3 |

Помесячный прогон 1–24 месяцев, сид 1729, та же величина: зерно 571.5 (m01) →
1248.0 (m24), соль 20.0 (m01) → 39.2 (m24), рента 0.0 (m01) → 74.3 (m24). **Ни один
месяц не даёт зерно 148.7 и рента 13.8.** Старое окно не воспроизводится ни на одном
горизонте и ни на одном сиде — это подтверждено перебором, а не утверждением.

## Замер (отпечаток дерева обязателен, ADR 0190/0191)

Отпечатки файлов, по которым сняты числа этого ADR:

```
sim/src/hillcourt/engine/tick.py            788ecb4712a2
sim/src/hillcourt/legal/obligations.py      7a889a769d77
sim/src/hillcourt/economy/manor.py          da9fb1787427
sim/src/hillcourt/engine/manor.py           4b90611c13e8
sim/src/hillcourt/economy/labor.py          (менялся в день замера, отпечаток не закреплён)
design/catalogs/obligations.yml             c01622f37862
design/scenarios/start_stand.yml            db2b2fc02c23
```

Дата замера — 29.09.2026. `economy/labor.py` в этот день правили другие агенты, поэтому
закреплять его отпечаток было бы фикцией: числа ниже приведены как **снимок**, а окно —
как диапазон, и диапазон переживает правку чужой зоны.

Команда снятия — ровно та, что стоит в `ACCEPTANCE.md` §Проверка:

```bash
PYTHONPATH=sim/src python3 -m hillcourt.runner \
  --scenario design/scenarios/start_stand.yml --months 24 --seed 1729
```

## Решение

1. **Новое окно `start_stand` (24 месяца, сид обязателен)** объявляется диапазоном, а
   не точкой. Диапазон — по двум замерам (сиды 1729 и 4242), округление — до «честного»
   шага, а не до прогона:

   | величина | окно | 1729 | 4242 |
   |---|---|---|---|
   | живых дворов | **7–8** | 8 | 8 |
   | ушло дворов | **0** | 0 | 0 |
   | голодных дворомесяцев | **0** | 0 | 0 |
   | соль в замке | **> 0** (было `20.0`) | 39.2 | 39.2 |
   | зерно в замке | **1000–1500** (было `148.7`) | 1248.0 | 1232.2 |
   | рента собрана | **50–100** (была `13.8`) | 74.3 | 70.0 |
   | `matter_delta` | **±0.000000** | −0.000000 | −0.000000 |
   | `state_hash` | снимок, не окно | `c6b6048d834a` | `ea375ed0504a` |

   Провал: дельта ≠ 0; соль `0.0`; голодных месяцев > 0; ушло дворов > 0.

2. **Старое окно не вытирается.** В `ACCEPTANCE.md` §1 остаётся строка с прежними
   числами, помеченная как «окно, которого не было»: она нужна, чтобы посторонний,
   нашедший число «148.7», узнал, что оно не измерение, а не ударился о пустоту.

3. **Окно объявляется здесь, а не подгоняется под прогон.** §5 `ACCEPTANCE.md` требует
   нового ADR на смену окна; этот ADR и есть такая запись. Дальнейшая смена окна — снова
   новый ADR, и снова по замеру, а не по факту прогона.

4. **Попутно в этом же ADR закрывается долг ADR 0200 №1** — см.
   [`0214_debt_0200_rent_is_closed.md`](0214_debt_0200_rent_is_closed.md): отдельная
   запись, потому что старые ADR не редактируются.

## Альтернативы

1. **Оставить старое окно и посчитать его «другим горизонтом».** Отклонено: перебор
   1–24 месяцев и двух сидов не даёт ни зерна 148.7, ни ренты 13.8 ни на одном шаге.
2. **Объявить окном точные числа прогона.** Отклонено запретом §5 `ACCEPTANCE.md` и
   ADR 0134: это подгонка под прогон, а не окно.
3. **Удалить старое окно без следа.** Отклонено: через месяц кто-то снова напишет
   «148.7» в документ, и уже нечем будет проверить.
4. **Объявить окно по одному сиду.** Отклонено: два сида показывают, что разброс
   (1248.0 против 1232.2 по зерну) мал, и диапазон шире измеренного — это запас на
   правку чужой зоны, а не подгонка.

## Последствия

- `ACCEPTANCE.md` §1 и §Проверка приведены в соответствие с этим ADR; в §1 осталась
  строка старого окна с пометкой.
- Числа стенда **разошлись с экономикой мира на 8.4 раза по зерну** (148.7 против
  1248.0). Любая приёмка, снятая на старом окне, считала стенд почти пустым.
- Ни один тест репозитория не проверял эти числа: окно было декларацией. Новых тестов
  на окно не заведено — окно проверяется командой §Проверка, а не тестом; это осознанно
  и совпадает с уже сказанным в `ACCEPTANCE.md`: приёмка — это runner-лог.
- `docs/09_economy.md` и `economy/` — зона Economist; числа окна смены экономики
  объявляются новым ADR, а не этой записью.

## Проверка

```bash
# Новое окно: снять оба замера и убедиться, что значения внутри диапазонов
PYTHONPATH=sim/src python3 -m hillcourt.runner \
  --scenario design/scenarios/start_stand.yml --months 24 --seed 1729 | tail -1
PYTHONPATH=sim/src python3 -m hillcourt.runner \
  --scenario design/scenarios/start_stand.yml --months 24 --seed 4242 | tail -1

# Старое окно не воспроизводится: помесячный прогон, сид 1729
PYTHONPATH=sim/src python3 - <<'PY'
from pathlib import Path
from hillcourt.scenario import load_scenario
from hillcourt.engine.tick import run_month
from hillcourt.runner import _apply_script_entry, _castle_stores, lord_income
w = load_scenario(Path('design/scenarios/start_stand.yml'), seed=1729)
script = list(w.script)
hits = []
for month in range(1, 25):
    for entry in script:
        if int(entry.get("at_month", 0)) == month:
            _apply_script_entry(w, entry)
    run_month(w)
    stores = _castle_stores(w)
    hits.append((month, round(stores.get("grain", 0.0), 1), round(stores.get("salt", 0.0), 1),
                 round(lord_income(w), 1)))
print("зерно 148.7 где-либо:", any(abs(g - 148.7) < 0.05 for _, g, _, _ in hits))
print("рента 13.8 где-либо:", any(abs(r - 13.8) < 0.05 for _, _, _, r in hits))
print("m01:", hits[0], "| m24:", hits[-1])
PY
# → зерно 148.7 где-либо: False / рента 13.8 где-либо: False
#   m01: (1, 571.5, 20.0, 0.0) | m24: (24, 1248.0, 39.2, 74.3)

# Строка старого окна осталась в документе с пометкой
grep -n "148.7" design/scenarios/ACCEPTANCE.md
```

Критерий: первый замер печатает `зерно 1248.0, соль 39.2; ренты собрано 74.3`,
второй — `зерно 1232.2, соль 39.2; ренты собрано 70.0`, оба с `дельта -0.000000`;
скрипт печатает `False`/`False`; `grep` находит строку старого окна в `ACCEPTANCE.md`.

**Не проверено 29.09.2026:** полный сюит (`bash sim/run_tests.sh`, ~22 мин) не
гонялся — это прогон хозяина; числа сняты узкими прогонами runner.

## Что запрещено следующим агентам

- **Не восстанавливать «148.7 зерна» и «13.8 рента» ни в одном документе.** Это числа
  из задания Critic, а не измерение; восстановление вернёт в окно приёмки вымысел.
- **Не менять это окно прогоном.** Окно меняется новым ADR, а не подгонкой (§5
  `ACCEPTANCE.md`).
- **Не ссылаться на этот ADR как на замер состава мира.** Состав баронства объявлен
  ADR 0207, окно баронства — §1a `ACCEPTANCE.md`.
