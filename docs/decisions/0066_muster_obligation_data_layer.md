# 0066. Слой данных вызова и отказа для союзного племени (владелец)

Дата: 2026-09-24. По проекту Legal (цикл 37) для v2 этапа племени (ADR 0062/0064).
Правит онтологию `Obligation`; код — после приёмки v1.

## Контекст

В v1 племя — данные (7 полей), оброк натуральный, вызов = проверка «может дать». В v2
союз/вассал должны отвечать на вызов и платить оброк (видение хозяина: «обязаны выставлять
солдат»). Legal: племя не `Household`, поэтому групповой вызов честно выражается набором
повинностей по одному на каждый племенный двор; `send_sally` переиспользовать нельзя
(другой правовой исполнитель); отказ нельзя выводить из отсутствия `Pack` (И-3) и нельзя
лепить `Pack.status=refused` (при отказе `Pack` не существует).

## Решение

1. **`Obligation` получает:** `kind += muster` (к `rent|labor_duty|levy`);
   `required_persons_count: int` (число голов — единица в имени по AGENTS); `call_status ∈
   {pending,met,refused,unable}`. Значения по умолчанию: `required_persons_count=0`,
   `call_status=pending` для не-`muster` повинностей (не влияет на оплату).
2. **Вызов племени — действие `call_tribe_muster` (v2, не v1).** Создаёт по одной
   `Obligation(kind=muster)` на каждый двор племени (состав — из
   `Settlement.household_ids` через биекцию `Tribe ↔ native_village`), только при
   `stance ∈ {allied,vassal}`; `send_sally` не используется.
3. **`Pack` рождается только когда люди вышли:** `kind=party`, `origin` = клетка племенной
   деревни, `member_ids` = фактически собранные, `owner_household_id=None`. Нет людей —
   нет `Pack`; невыполненная повинность остаётся в `call_status`.
4. **Честный отказ:** `refused` ставится, когда племя actively отказался (действие/решение
   племени, v2), `unable` — когда не мог (нет людей/комплектов/корма); различать их можно
   только через решение племени, не через отсутствие вести у игрока. Весточка идёт
   существующими каналами.
5. **Оброк и вызов не смешиваются:** натуральный оброк остаётся `levy` с оплатой/arrears;
   `muster` — про людей. `war_kit` тэна не переиспользуется как норма племени.

## Альтернативы

- `Pack.status=refused` — отклонено: при отказе `Pack` не создан, статус был бы ложью.
- Отказ выводить из тишины/отсутствия вести — отклонено (И-3: весть не истина).
- Новая сущность «Вызов»/«Повинность племени» — отклонено: хватает расширения
  `Obligation` двумя полями и одним enum.
- `send_sally` для племени — отклонено (ложный исполнитель).

## Последствия

- Онтологию правит Scribe по этому ADR; `Obligation` — сущность Legal.
- Реализация v2: Legal (каталоги/бандл вызова), Implementer (действие + сбор `Pack`),
  Economist (норма/потолок), Info (вести о вызове/отказе). Слои не вшиваются до приёмки v1.
- Бюджет: это рычаг холма (служба союзника = доход и защита), но цена высокая — порядок
  строго v1 → приёмка → v2 микро-шагами.

## Что запрещено следующим агентам

1. Выводить отказ из отсутствия `Pack` или из молчания.
2. Использовать `send_sally`/`war_kit` тэна как племенную норму.
3. Создавать `Pack` без фактически вышедших людей.
4. Смешивать оброк и вызов в одной повинности.

## Проверка

```bash
bash sim/run_tests.sh
```

Критерий: сюит зелёный; тест на `muster`-повинность (по одному на двор, только при
`allied|vassal`); тест «нет людей — нет `Pack`, `call_status=unable`»; тест «отказ ≠
молчание» (решение племени → `refused` + весть); дельта 0; канон в окнах.
