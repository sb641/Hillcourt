# 0026. Новые тайлы вида: лагеря, переправа, поле господина, железница

Дата: 2026-09-21. Зона: наполнение тайла и контракт вида (продолжение 0024).
Чужое не тронуто: служба тэна, реки как механика, скот, yield, барщина,
pathfinder, каталоги Economist/Legal, сценарии, спрайты/`client/`.

## Контекст

Заказ: походные лагеря (пеший с котелком, с костром, с палатками, с шатрами,
с повозками, укреплённый с частоколом), пристань/переправа/торговые лодки,
шахта, каменоломня, тайлы под конкретные лесные действия, поля господина.
Ограничения из 0024 и конституции: вид следует из состояния (не ручная краска),
без экономического бонуса (И-5), без лора без сущности (И-8), кап 5 и кап
пашни G3 не ломать.

Что есть в данных (проверено чтением, не выдумано):
- Возы: `Pack` (`party` от `send_party`/`send_march`, `caravan` по правилам
  `caravan_visit`/`caravan_grain_to_ash`, `household_move` миграции) с
  `destination_tile_id`, `member_ids`, `owner_household_id`, `status`.
  Профиль хода (`foot`/`caravan`/…) на `Pack` НЕ хранится (только в логе
  `send_march`), поэтому тип лагеря выводится из рода воза, ранга владельца
  и силы отряда, а не из профиля.
- Послать можно только пресеты `geneat`/`thegn` (`can_be_taken_on_expedition`;
  `holder`/`sokeman`/`villein`/`cotter`/`free_landless`/`slave` — нет).
- Переправа: флаги `Tile.ford`/`bridge`; вода без них непроходима
  (`engine/terrain.py`); товары `raft`/`boat` и рецепты `craft_raft`/`craft_boat`
  существуют — плоты и лодки те же ворота через воду.
- Поле господина: режим `demesne` (`land_regimes.yml`) + `terrain field`.
- Железо: только болотное (`mine_iron` на `marsh`, рост `grow_iron`, товар
  `iron`); шахты-штольни в сеттинге нет. Камня нет вовсе (нет good/recipe).
- Лес: `cut_firewood`/`cut_wood` (`place: tile`, `requires_terrain: [forest]`),
  `forage_wild` (соседние клетки). Охота как решено ранее — рандом, не тайл.

## Решение

Каталог `FORMS` в `engine/tile_view.py`: 7 → 17 (городов по-прежнему нет).
Приоритет: зал корня > усадьба тэна > переправа > лагерь > поле господина >
счётчик дворов. Новое никогда не перекрывает seat и не меняет кап.

- `lord_field` (Поле господина): `regime demesne` + `terrain field` + 0 дворов,
  не seat. С жителем — уже `single_homestead`/`village` (вид людей важнее клина).
- `crossing` (Переправа): `ford`/`bridge`. Покрывает и пристань плотов, и
  торговые лодки как ворота через воду (один тайл на «либо-либо» из заказа).
- `bog_iron` (Болотная железница): пустая топь (`terrain marsh`). Изменение
  против 0024 (там топь была `waste`): сеттинг-честно, железо у нас болотное;
  `waste` теперь только heath/salt_flat/ruin/water.
- Лагеря — только `in_transit` воз к клетке (дошедшие/погибшие следов не
  оставляют). Выбор детерминирован: сортировка по (`kind`, `id`), первый задаёт:
  `caravan` → `wagon_camp` (повозки); `household_move` → `tent_camp` (палатки
  переселенцев); `party` владельца `holder`/`thegn` → `pavilion_camp` (шатры);
  иначе по силе: ≥4 (`FORTIFIED_MIN_MEMBERS`) → `fortified_camp` (частокол),
  ≤2 → `foot_pot_camp` (котелок дозора), ровно 3 → `campfire_camp` (костёр).
  Пороги — правила вида (аналог 0/1/много у дворов), не краска.
- `quarry` (Каменоломня) — РЕЗЕРВ иконки: `tile_form` её не возвращает;
  триггер появится только с сущностью у Economist (камень как good + рецепт).
- Лес без новых тайлов: дрова/валка/сбор идут по соседним клеткам
  (`economy/labor.py`, доступ по `legal/regimes.py`), вид остаётся `forest` —
  та же логика, что у охоты-рандома. Лесосека как отдельный тайл не требуется,
  пока нет сущности (яма/углежог) у Economist.

Пример дампа (`v0_hill_and_salt`):

```text
t_06_02 field lord_field дворов=0 seat=0 hall=0
t_02_03 marsh bog_iron дворов=0 seat=0 hall=0
t_06_02 + party(1) → foot_pot_camp; + party(3) → campfire_camp
t_06_02 + party(4) → fortified_camp; + party тэна → pavilion_camp
t_04_00 + caravan → wagon_camp; + household_move → tent_camp
```

Проверка: `sim/tests/test_tile_camps.py` (16 зондов), старые
`test_tile_view.py` (13) зелёные; `bash sim/run_tests.sh` — 362 OK, дельта 0,
каноны соли/зерна (11.6, ratio) те же — экономика не двинулась.

## Альтернативы

- Тип лагеря из профиля хода (`foot`/`mounted`): отвергнуто — профиль на `Pack`
  не хранится (только в логе), вид не может читать лог приказа.
- Все топи оставить `waste`, шахту вывести стоячим `iron` ≥ порога: отвергнуто —
  запас мерцает (рост/выборка), иконка фlickерила бы; terrain стабилен и честен.
- Каменоломня из `terrain hill`: отвергнуто — карьер без камня в каталоге есть
  лор без сущности (И-8, брак); только резерв.
- Лесосека по решению двора (`main_action == cut_wood_if_allowed`): отвергнуто —
  решение месячное и мерцает, вид дёргался бы; лес остаётся лесом.
- Лагерь из `arrived`-возов (след стоянки): отвергнуто — возы живут вечно,
  клетка залипла бы в лагере навсегда.

## Последствия

- Рендер получает 10 новых слотов иконок без единой новой сущности мира;
  `TileView` (поля) не менялся — контракт обратно совместим.
- Пустая топь теперь `bog_iron`, а не `waste` (единственное изменение старых
  форм; старые тесты не задеты — топь ими не проверялась).
- `quarry` ждёт Economist (камень) — активация новым ADR, не правкой этого.

## Что запрещено следующим агентам

- Возвращать `quarry` из `tile_form` без камня в `goods.yml`+рецепта (И-8).
- Давать любой новой форме бонус (урожай/труд/служба/проход): вид — рендер.
- Читать профиль хода из лога приказов для вида; хранить профиль на `Pack`
  ради иконки (чужое — зона пути).
- Перекрывать новой формой seat'ы и кап 5; заводить городской тайл.
- Класть спрайты/текстуры в `sim/`; править каталоги Economist/Legal и сценарии
  ради вида (только через владельцев).
