# 0010. Контракт амбара тэна: stock_id, grant, revoke, голод

## Контекст

Догон к сущности Manor (ADR 0008). Факт: `grant_thegn` переносил право, а хозяйство тэна было
выключено — пул трудодней писался в `Manor.demesne_labor_filled`, но амбара у тэна не было,
пожалованный двор не кормился ни в замке, ни у тэна. Это дыра, а не модель «самостоятельного
тэна». Формулировка «сгорание дней = фича v0» снимается и записывается как **закрытый долг**.

Роль: Manor Implementer. Зона: manor grant/revoke, права, `docs/08`/`docs/09`. Экономисту —
только принадлежность амбара; трудодни и yield не пересчитываются.

## Решение

1. **`Manor.stock_id` обязателен.** Корень — `settlement:hill_court` (существующий замок).
   Тэн — `manor:<id>`, заводится в `grant_thegn` (не позже). `grant_thegn` без создания
   амбара запрещён; если id занят не манором (`owner_kind != "manor"`) — отказ.
2. **Одна книга на двор.** `Household.manor_id` — единственный адрес стола. Сценарий
   проставляет `manor_id = manor_hill` тяглым дворам; `grant_thegn` переводит пожалованные
   дворы на `manor_id` тэна, `revoke_thegn` возвращает на корень. Оставить двор без книги
   нельзя. `manor_of_household` читает `manor_id` (fallback — `household_ids`).
3. **Домен обязателен.** Режимы клеток при grant не меняются (tenement остаётся tenement),
   но среди пожалованных клеток должна быть ≥1 `regime:demesne`. Иначе `grant_thegn`
   отклоняется. Альтернатива «писать `wasted_labor_days`» не выбрана: третий путь не нужен.
4. **depth ≤ 1, второй тэн не создаётся** (`root.grant_ids`), тэн не жалует дальше.
5. **revoke.** Земля, дворы и **амбар** тэна сливаются в родителя через `Ledger.transfer`
   (good by good), затем мёртвый `manor:<id>` снимается. Зерно не двоится, не сгорает, не
   остаётся на мёртвом id; `world.total_matter()` сохраняется.
6. **Голод тэна.** `mustered = держатель жив и не голоден ПО СВОЕМУ двору/стоку`
   (`thegn_hungry` → `household.hunger_days`), не по замку холма. Обновляется в
   `phase_record`.
7. **Помочи.** `call_boon` / `ease_week_work` в v0 — только корень; тэн помочи не кричит.

## Альтернативы

- **Оставить пул write-only** — отклонено: двор тэна без стола, дни сгорают.
- **`wasted_labor_days` вместо домена** — отклонено в пользу отказа grant: проще и честнее
  (тэну нечего пахать — не жалуем).
- **Менять режим пожалованной клетки на `demesne`** — отклонено: режимы при grant не меняем.
- **Отдельный сток на каждый двор** — отклонено: книга одна, сток у манора.

## Последствия

- `Manor.stock_id`, `Household.manor_id` в онтологии; `state_hash` покрывает оба.
- `grant_thegn` создаёт `manor:<id>`, переводит `manor_id`, требует домен; `revoke_thegn`
  сливает амбар и снимает его; `thegn_hungry` для `mustered`.
- `test_manor_entity.py` (21 тест): grant без амбара и без домена отклонён; `manor_id` у тэна;
  revoke — сумма зерна корень+тэн до = корень после (дельта 0); второй grant отклонён;
  `mustered` по своему стоку.
- Экономист переводит `_board`/`_gafol`/`_sow_demesne`/урожай на `manor.stock_id` двора;
  трудодни не пересчитываются. Статус: паёк (`_board`) уже по амбару манора; сбор/урожай
  тэна — в работе.

## Что запрещено следующим агентам

1. Регистрировать манор без `stock_id` или переиспользовать чужой сток под амбар.
2. Оставлять двор без `manor_id` (без книги/стола) после grant.
3. Жаловать без доменной клетки; менять режимы клеток при grant.
4. Оставлять мёртвый `manor:<id>` или терять/двоить зерно при revoke.
5. Считать `mustered` по замку холма, а не по стоку держателя.
6. Давать тэну кричать помочи/урезать барщину в v0.
