# 0064. Племя v1 урезано по бюджет-гейту (владелец, отменяет 0062/0063 в части полей)

Дата: 2026-09-24. Уточняет 0062/0063 (старые не правятся). Принял замечания Systems-гейта:
сущность тонкая политическая надстройка совместима с конституцией, но набор полей 0062
рисковал дублями книг, скрытым tech-tree и всеведением.

## Контекст

Systems-гейт по `Tribe`: `household_ids` дублируют `Settlement`, `land_tile_ids`/`granted_land`
превращают племя во вторую земельную книгу, `own_economy`/`law_profile` — скрытый tech-tree,
`muster_profile`/`muster_obligation` — скрытая военная система, `loyalty` — скрытая шкала
с последствиями (И-3), `annexed` — мёртвое состояние в v1, «своя книга» = второй `Manor`
(запрет). Обязательные условия: биекция `Tribe ↔ Settlement.kind=native_village` (один к
одному), состав и общая земля вычисляются, никаких полей-кэшей, месячный контур без новой фазы.

## Решение

**`Tribe` v1 = `{id, name, stance, settlement_id, tribute_grain, muster_kits}`** —
и больше ничего. Правила:
1. **Биекция:** один `Tribe` на одно `Settlement.kind=native_village`; `settlement_id` —
   единственная ссылка. Два племени на деревню или деревня без племени — отказ загрузки.
2. **Состав вычисляется** из `Settlement.household_ids`; поля `household_ids`,
   `land_tile_ids`, `granted_land`, `own_economy` в v1 **нет** (дубли и вторая книга).
3. **Общая земля = `Right.kind=common`** (ADR 0060) + `works_tiles`; `grazing` — личное
   решение барона (ADR 0062 уточнение). Племя не владеет клетками само.
4. **Своя книга запрещена:** ни амбара, ни `Manor`, ни подчинённых книг. Внутренняя
   экономика — существующие `Household`/`Stock`/`Recipe`.
5. **Оброк v1 — только натуральный:** `tribute_grain` (0.6/мес на двор племени, как сокмен)
   через существующий `levy`-механизм; неоплата → `arrears`; платится только при
   `allied|vassal`. Денежная/смешанная схема — v2.
6. **Вызов v1 — данные:** `muster_kits` (сколько комплектов племя может дать); проверка
   «может дать» = взрослые в составе + комплекты. Нового вызова/handler, `send_sally` и
   `muster_profile` в v1 нет. Групповая повинность — v2 отдельным ADR.
7. **`loyalty` в v1 нет** (скрытая шкала = всеведение, И-3). Натяжение видит только игрок
   через `Report`, и только в v2.
8. **`annexed` не состояние, а переход v2:** в v1 стойки — `independent|allied|vassal`.
9. **Тик:** месяц, без новой фазы; переиспользуются `phase_obligations`/`phase_record`,
   сортировка по id (И-4).

## Альтернативы

- Оставить `loyalty`/`muster_profile`/`law_profile` в v1 — отклонено: скрытые шкалы и
  tech-tree, бюджет и И-3.
- `own_economy` у племени — отклонено: вторая книга = второй Manor.
- Два племени на одной деревне — отклонено: два источника состава разойдутся.

## Последствия

- Онтологию правит Scribe по этому ADR (7 полей, не 12).
- Код v1: загрузка племени из YAML (Implementer), guard ухода по
  `Settlement.kind=native_village` (Implementer), оброк через существующий `levy`
  (Economist, его зона), тест «может дать вызов» (Economist/Implementer по границе).
- Племя — только видна/торгуемая сущность с оброком и потенциалом вызова; дипломатия,
  вызов-действие, мятеж, `Community` — v2, каждый своим ADR.
- Канон не должен сдвинуться (племя — отдельная клетка/сценарий); дельта 0.

## Что запрещено следующим агентам

1. Поля-кэши в `Tribe` (состав/земля/книга/loyalty) — вычисляются или ждут v2.
2. Второй `Manor`/амбар под племя; `own_economy`.
3. `muster_profile`, `send_sally` как племенной вызов, групповые повинности в v1.
4. Показывать игроку `stance`/`loyalty` точно (только `Report`, приблизительно).
5. Биекцию нарушать: два племени на деревню / деревня без племени.

## Проверка

```bash

```

Критерий: сюит зелёный; `Tribe` = 7 полей; биекция в загрузчике (тест); уход дворов
нативной деревни не срабатывает (тест); оброк платится/`arrears` только при
`allied|vassal` (тест); `muster_kits` не дают действия в v1; дельта 0; канон в окнах.
