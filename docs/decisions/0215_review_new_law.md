#### 1.2. НАХОДКА 1 — в целевом мире `v0_barony_100` проигрыш НЕ ДОСТИЖИМ ни одним из двух законов (серьёзно)

**Что.** Оба закона ADR 0209 в `v0_barony_100` — самом большом и целевом мире репозитория —
недостижимы честной игрой. Проверено не рассуждением, а тремя независимыми прогонами.

**Где.** `sim/src/hillcourt/engine/ruin.py:74` (`ABANDONED_LEFT_MIN = 2`), `:78`
(`ABANDONED_SHARE = 0.25`), `design/catalogs/legal_statuses.yml` (`can_leave`).

**Как воспроизвести.**

```bash
# (1) «Крестьяне ушли»: потолок доли в целевом мире
PYTHONPATH=sim/src python3 -c "
from pathlib import Path
from hillcourt.scenario import load_scenario
from hillcourt.legal.regimes import can_leave
w = load_scenario(Path('design/scenarios/v0_barony_100.yml'), seed=4242)
for sid, s in sorted(w.settlements.items()):
    live = [h for h in s.household_ids if w.households[h].left_at is None]
    if s.kind in ('native_village', 'salt_village'):
        continue
    f = sum(1 for h in live if can_leave(w, w.households[h]))
    print(sid, 'дворов=%d могут_уйти=%d потолок=%.1f%%' % (len(live), f, f/len(live)*100))
"
```

```
hill_court      дворов= 90 могут_уйти= 3 потолок=  3.3%
village_forest  дворов= 24 могут_уйти= 0 потолок=  0.0%
```

Порог `ABANDONED_SHARE = 0.25` требует ухода **23 дворов из 90**. Уйти могут **три**:
86 `villein` заперты `can_leave: false`. **Разрыв в 7.7 раза.**

```bash
# (2) «Семейство банкроты»: честная игра — сеньор снимает домен и кормит двор.
#     Это в точности рецепт ADR 0209 из v0_ruin_bankrupt, перенесённый на баронство.
#     v0_barony_100, 60 мес, сид 4242, m6: снять ВСЕ 23 доменные клетки в tenement
#     + grant_grain 6.0/мес  →  lord_hunger = 0 ВСЕ 60 МЕСЯЦЕВ, is_lost = False,
#     barn растёт до 2896.
# (3) отдать можно ровно столько, сколько игрок ВИДИТ в вести (confidence 1.0):
#     v0_barony_100, 30 мес, grant_grain ровно = содержимое амбара
#     → barn опускался до 0.24 (m25), lord_hunger = 0, is_lost = False.
# (4) 400 зерна/мес сверх остатка (35 отказов из 48) → lord_hunger = 0 все 48 месяцев.
```

**Почему это важно.** Три замера, три независимых способа разорить сеньора, все — молчание:

| способ | баронство | `v0_ruin_bankrupt` (контроль) |
|---|---|---|
| снять домен + кормить двор (рецепт ADR 0209) | `hunger=0` 60/60 | `hunger=3` на m53 |
| отдать весь амбар корня, зная точное число | `hunger=0` 30/30 | — |
| 400 зерна/мес сверх остатка | `hunger=0` 48/48 | — |

Причина измерена: нужда двора сеньора — **3.40 зерна/мес** (4 человека, паёк `holder` = 1.0
на рот-единицу), а амбар `manor_hill` растёт до **2896**, и оброк со 150 дворов надёжен.

**Минимальный контрпример — числа, не слова.**

```
v0_barony_100, 60 мес, сид 4242, приказы игрока исполняются:
  m006 barn= 745.45  lord_hunger=0
  m030 barn=1501.61  lord_hunger=0
  m060 barn=2896.47  lord_hunger=0   is_lost = False
```

**Почему это нарушение.** Формально — ни одного нарушения И-1…И-10: законы написаны верно,
тесты зелёные, ADR 0209 §Замер **сам** признаёт потолок 2.6 % в баронстве. Но хозяин
постановил «проигрышей ровно два» — и **в игре, в целевом мире, проигрыша нет ни одного**.
ADR 0209 §Решение 1 признаёт это для «крестьян», а про «семейство банкроты» пишет обратное:
«Выбор из четырёх кандидатов хозяина… **ДА, это закон**», и таблица §Замер даёт
`v0_ruin_bankrupt` как разоряющийся мир.

Проверки, которая бы это поймала, **нет**: `sim/tests/test_barony_100.py` не упоминает
проигрыш ни разу (`grep -n "ruin\|is_lost\|bankrupt\|abandon"` → пусто), а
`test_ruin_reachable.py:236` проверяет обратное — `test_barony_100_does_not_lose`.

То есть закон **проверен на то, что в целевом мире проигрыша нет**, и это подано как успех
приёмки. Это ровно то, что ADR 0155 называет законом без падающей проверки: есть проверка
«проигрыша нет», нет проверки «проигрыш достижим».

**Кому.** ADR 0209 (author), `engine/ruin.py` (Implementer), решение о балансе — хозяин.

#### 1.3. НАХОДКА 2 — «семейство банкроты» в целевом мире заперто структурно, а не порогом (серьёзно)

**Что.** Даже если хозяин захочет сделать проигрыш достижимым, порог
`FAMILY_HUNGER_MONTHS = 3` тут ни при чём: заперта **раздача**. `manor_month`
(`economy/manor.py:642`) зовёт `_board` **после** гэфоля, найма и урожая, то есть за месяц
амбар успевает наполниться дважды, и паёк лорда почти никогда не оказывается под вопросом.

**Где.** `sim/src/hillcourt/economy/manor.py:642` (`_board(world, date)` — последний шаг
месяца), `design/catalogs/manor.yml:46-51` (`grain_per_adult_by_status: holder: 1.0`).

**Почему это нарушение.** Тот же класс, что и НАХОДКА 1 из `0208`, только глубже: не число,
а **механика, которая не может дать эффект**. Игрок, выбравший «разорить сеньора», обнаружит,
что ни один его рычаг туда не ведёт: `grant_grain` берёт из того же амбара и отказывается при
нехватке, `relief` платит из того же амбара, снятие домена не помогает (проверено).
Раздача не сломана — она **слишком щедра** к должнику, и это не замерено ни одним тестом.

**Минимальный контрпример.**

```
v0_barony_100, m1..m8: нужда лорда = 3.40 зерна/мес, barn = 56.7 -> 1093.7,
                       hunger = 0 весь срок. Чтобы голодать, нужен barn < 3.4
                       при оброке > 150/мес — такое состояние не наступает.
```

#### 1.4. НАХОДКА 3 — защёлка «крестьяне ушли» не сверяется с разбивкой (мелко, но это ровно «защёлка, которую забывают»)

**Что.** `is_lost()` читает только защёлки. `RunResult.abandoned_settlements` — это
**живой пересчёт** (`runner.py:760-762`), а не чтение защёлки. Две величины живут по разным
правилам, и согласованность между ними не проверяется нигде.

**Где.** `engine/ruin.py:296` (пишет `RUIN_PEASANTS_LEFT`) и `engine/ruin.py:272-274`
(`peasants_left` читает защёлку) против `runner.py:760-762` и `runner.py:804-806`
(`if result.abandoned_settlements:`).

**Как воспроизвести.**

```bash
PYTHONPATH=sim/src python3 -c "
from pathlib import Path
from hillcourt.scenario import load_scenario
from hillcourt.engine import ruin as R
w = load_scenario(Path('design/scenarios/start_stand.yml'), seed=1729)
w.stats[R.RUIN_PEASANTS_LEFT] = 1.0
print('is_lost:', R.is_lost(w),
      '| abandoned_settlements:', [a.settlement_id for a in R.abandoned_settlements(w)])
"
```

```
is_lost: True | abandoned_settlements: []
```

**Почему это нарушение.** `runner.py:798-808`: при `result.lost` и **пустом**
`abandoned_settlements` и `family_bankrupt = False` список `reasons` пуст, и строка
печатается как **`ПРОИГРЫШ: `** — с пустым хвостом. Игрок видит «проигрыш» без причины.
В честном прогоне путь недостижим (`phase_ruin` пишет защёлку и пораздельную метку в одном
такте, `ruin.py:295-296`), поэтому это **не сегодняшний ущерб** — но это ровно тот класс
«write-only защёлки», ради которого блок задан.

**Кому.** `runner.py` — зона Implementer. Правка тривиальна: `abandoned_settlements` строить
из `world.stats[RUIN_ABANDONED_PREFIX + id]`, а не пересчитывать.

#### 1.5. Мелочь, не дефект

`hunger_days` (`ontology.py:105`) называется `_days`, а `phase_consume` (`tick.py:344`)
увеличивает его **раз в месяц**. ADR 0209 и `family_hunger_months` читают его как месяцы —
семантика **совпадает** (замерено: +1 за месяц). Но имя поля враёт, и `world.state_hash()`
(`world.py:83`) печатает `hunger_days` в хеш, то есть подпись `_days` уедет в любые окна
приёмки. Отмечаю, чтобы Scribe не перевёл «дни» в документе.

| мемо создаёт материю? | **НЕТ**: `tile_feeds_household` — чистая функция рельефа по каталогу, возвращает `bool` |

**И-1 не нарушена нигде.** Новый код материю не двигает.

### 5. Вести (Блок 5)

ADR 0205 и ADR 0212 починили то, что первый критик нашёл (подпись «Холм» больше не называет
поселение гексом; весть о поселении пошла слухом от шерифа, глаз остался точным по клетке).
Всёведение не открыто: `facts` — плоские числа, `build_player_view` (`news/views.py:69-78`)
читает только доставленные `Report`. **И-3 цела.**

#### 5.1. НАХОДКА 5 — в вести шерифа есть БЕЗОШИБОЧНЫЙ канал: разности между поселениями (серьёзно)

**Что.** ADR 0209 §Решение 5 требует «один бросок на весь отчёт», чтобы отчёт не
противоречил сам себе. Исполнено буквально — и этим **уничтожен шум**.

`_report_messenger` (`briefing.py:377-393`) берёт **один** `drift` и применяет его и к
недоимке, и к **каждому** поселению в `left_by_settlement`. Значит во всех числах разбивки
сидит **один и тот же** шум, и при вычитании он **уничтожается**:

```
сообщено(A) - сообщено(B) = (A+drift) - (B+drift) = A - B   — ТОЧНО, без шума.
```

**Где.** `sim/src/hillcourt/info/briefing.py:385-393` (`drift = rng.choice([-1, 0, 0, 0, 1])`,
затем `left_reported = {sid: max(0, count+drift)}`). Та же конструкция продублирована в
`news/ruin.py:87` (`COUNT_DRIFT`), применяется в `:201` и `:250` и там же.

**Как воспроизвести.**

```bash
PYTHONPATH=sim/src python3 -c "
from pathlib import Path
from hillcourt.scenario import load_scenario
from hillcourt.info import briefing as B
from hillcourt.ontology import SimDate
w = load_scenario(Path('design/scenarios/v0_barony_100.yml'), seed=4242)
for sid, n in {'hill_court': 5, 'village_forest': 11}.items():
    for h in w.settlements[sid].household_ids[:n]:
        w.households[h].left_at = SimDate(1, 1, 1)
print('истина:', B.left_by_settlement(w))
for _ in range(400):
    B._report_messenger(w, w.clock.date, 't_45_50', w.rng.news)
    r = [x for x in w.reports if x.facts.get('departed_households') is not None][-1]
    d = r.facts['left_by_settlement']
    print(d, 'разность=', d['hill_court'] - d['village_forest'])
"
```

```
истина: {'hill_court': 5, 'village_forest': 11}
{'hill_court': 4, 'village_forest': 10}  разность = -6   (истина -6)
{'hill_court': 6, 'village_forest': 12}  разность = -6
{'hill_court': 5, 'village_forest': 11}  разность = -6
...
разность за 400 сообщений: [-6]  ->  ВСЕГДА -6, безошибочно
```

**Почему это нарушение.** Не формальное И-3 (истины в `facts` нет — только целые со сдвигом),
а **смысл закона шума**: `docs/05_information.md:70` объявляет для `messenger` «счёт дворов
с недоимкой дрейфует на **±1**», и разброс — то, что делает канал слухом. Здесь разброс есть
только у **абсолютных** чисел; **все производные величины точны**. Шум, объявленный как
«типичный разброс канала», предсказуем — а задание называет систематический шум честной дырой.

**Минимальный контрпример.** Истинные уходы `hill_court` 5, `village_forest` 11. Игрок
видит `4 и 10` — и **безошибочно** знает, что разность 6. При независимом шуме на каждое
поселение он видел бы 9 возможных разностей и сузил бы истину до трёх кандидатов.

**Кому.** `info/briefing.py` — зона Info. ADR 0209 авторизовал «один бросок» как
**согласованность отчёта**; согласовать можно, не делая шум вырожденным.

#### 5.2. НАХОДКА 6 — флаг `distorted` превращает 60 % месяцев в точные данные (средне)

**Что.** `Report.distorted` доходит до игрока (`news/views.py:65`). Для шерифского отчёта
`distorted = reported != true or departed != sum(true)`, а дрейф — `(-1,0,0,0,1)`. Значит
**с вероятностью 3/5 = 60 %** флаг равен `False`, и в этом месяце сообщённое число —
**буквально истина**. Игрок читает «шериф не исказил» — и получает точный ответ из канала,
которому положено `confidence 0.5`, `noise 0.15`.

**Где.** `briefing.py:410` (вычисление `distorted`), `:385` (`rng.choice([-1, 0, 0, 0, 1])`),
`news/views.py:65` (`distorted=report.distorted`).

**Как воспроизвести.**

```bash

14  True             |  16  False             |  18  True
```

**Почему это нарушение.** ADR 0205 и ADR 0212 строят на одном принципе: «**достоверность
1.0 законна, только когда свидетель — сам держатель**» (`briefing.py:12-14` (закон ADR 0205 в докстринге модуля)). Здесь
`confidence 0.5`, свидетель — шериф, а игрок получает число, помеченное как **не искажённое**,
то есть как истинное. И-3 формально не нарушена, но `docs/05_information.md:70-72` превращён
в тихий точный канал.

#### 5.3. НАХОДКА 7 — точный глаз полностью перекрывает слух шерифа на шести мирах из девяти (средне)

**Что.** ADR 0212 §Решение 6 утверждает: «точного числа поселения игрок по-прежнему не знает
— он знает слух». На всех мирах, где поселение = одна клетка (а их **шесть из девяти**), это
неверно: глаз (`confidence 1.0`, `noise 0.0`, `subject_kind="tile"`) и есть сумма по поселению,
то есть игрок знает её **точно и без шума**. Слух шерифа рядом — просто дубликат с шумом.

**Где.** `info/briefing.py:80-127` (`_report_court`, точное зерно клетки) против
`:170-227` (`_report_settlement_grain`, слух).

**Как воспроизвести.**

```bash
PYTHONPATH=sim/src python3 -c "
from pathlib import Path
from hillcourt.scenario import load_scenario
from hillcourt.engine.tick import run_month
from hillcourt.runner import _apply_script_entry
from hillcourt.engine.seat import court_tile_id
for scen in ['start_stand', 'v0_hill_and_salt', 'v0_shire']:
    w = load_scenario(Path('design/scenarios/%s.yml' % scen), seed=1729)
    court = court_tile_id(w)
    s = w.settlements[w.player.court_settlement_id]
    script = list(w.script)
    for m in range(24):
        for e in script:
            if int(e.get('at_month', 0)) == m + 1:
                _apply_script_entry(w, e)
        run_month(w)
    cell = [h for h in sorted(w.households)
            if w.households[h].left_at is None and w.households[h].current_tile_id == court]
    sett = [h for h in sorted(s.household_ids) if w.households[h].left_at is None]
    g = lambda hs: sum(w.get_stock(w.households[h].stock_id).amounts.get('grain', 0.0) for h in hs)
    eye = [x for x in w.reports if 'grain_approx' in x.facts and x.subject_id == court][-1]
    print(scen, 'гекс==поселение:', abs(g(cell) - g(sett)) < 1e-9,
          'ГЛАЗ=', eye.facts['grain_approx'], 'ИСТИНА=', round(g(sett), 1))

```

```

v0_hill_and_salt   гекс==поселение: True   ГЛАЗ=112.1 ИСТИНА=112.1
v0_shire           гекс==поселение: True   ГЛАЗ= 91.2 ИСТИНА= 91.2
```

**Почему это важно.** ADR 0212 выиграл спор с первым критиком правильно (подпись стала
честной), но **создал новый обман поменьше**: шериф теперь ежемесячно сообщает «по его словам,
около N» о числе, которое игрок **уже знает точно** с глаза. Игрок, поверивший шерифу (как его и
приглашали — «по его словам»), будет считать, что его город непредсказуем, а он предсказуем до
зерна. Либо весть о поселении лишняя на малых картах, либо глаз должен быть шумным — и ADR 0212
это решение принял неявно, не записав.

**Почему это не выглядит всеведением.** Не выглядит: точного числа **поселения шире клетки**
игрок не получает, и в `v0_barony_100` (где поселение = 8 кварталов) глаз честно показывает
13 % столицы. И-3 цела.

### 6. Слепые сторожи (Блок 6)

#### 6.1. Новый AST-сторож — НАСТОЯЩЕ строже, это не косметика

Проверял и на дереве, и на подделках.

| подмена | старый regex | новый AST |
|---|---|---|

| `note = 'court'` (строка) | оживлял | не оживляет ✓ |
| новое поле без читателя | ловил | **ловит** ✓ (проверено: `critic_dead_probe` в `Good` -> КРАСНЫЙ) |

Находка 5 первого критика (`LegalStatus.court` слепой) закрыта по существу: `court` теперь в

это перечислил и отдал хозяину; моё подтверждение: список полон, шестнадцатого мёртвого поля нет.

   `confidence 0.5`. Флаг, который означает истину, — это истина.
5. **Отметить разности поселений как «приемлемую погрешность».** Отклонено: погрешности нет —
   разность точна при любом дрейфе, то есть шум канала на производных величинах **равен нулю**.
6. **Оставить отчёт без ADR.** Отклонено: `AGENTS.md` §4 п.6 требует запись, если решение
   спорное; список законов не в силе адресован хозяину и обязан лежать в дереве.
7. **Взять номер 0214, как велено буквой.** Отклонено: `0214` занят
   (`0214_debt_0200_rent_is_closed.md`). Задание само велило проверить `ls docs/decisions/`;
   проверка показала занятость, поэтому запись получила 0215, а не перезаписала чужую.

## Последствия

- **Проигрыш в игре отсутствует.** Оба закона ADR 0209 в `v0_barony_100` недостижимы
  (НАХОДКИ 1.2, 1.3). Три способа разорить сеньора измерены и дали молчание.
- **Проверка «проигрыша нет» есть, проверки «проигрыш достижим» нет.** `test_barony_100.py` о
  проигрыше не знает; `test_ruin_reachable.py:236` проверяет отсутствие проигрыша и подаёт это
  как приёмку.
- **В вестях шерифа есть точный канал** — производные от `left_by_settlement` и 60 % месяцев с
  `distorted=False`. И-3 формально цела, смысл канала сломан (НАХОДКИ 5, 6).
- **Окна приёмки ADR 0213/0214 не защищены тестом**, а объявленные в них хеши уже не про этот
  мир (НАХОДКА 4).
- **`Good.storage`** — мёртвое обещание на 55 товаров, заполненное правдоподобными значениями;
  И-7 проверяет ярлык, а не свойство (НАХОДКА 9).
- **Сторож стал настоящим**, но обман переехал в `Store`-контекст и в одноимённые поля чужих
  объектов (НАХОДКА 8).
- **Оптимизация `economy/labor.py` чиста** — ни одной находки.
- **И-1, И-3, И-6 целы** на всём проверенном.
- Стендовое время завышено: машина делилась с Table. Числа надёжны, оценки скорости — нет.

## Список законов, которые не в силе

Проверены словом, а не падающей проверкой. По этому списку хозяин строит тесты.

1. **ADR 0209 §Решение 1 — «крестьяне ушли» как проигрыш.** Проверка есть, и она зелёная,
   но она проверяет **не то**: `test_ruin_reachable.py:236` утверждает, что баронство
   проигрыша не имеет, и подаёт это как приёмку. Проверки «проигрыш достижим **в целевом
   мире**» нет ни в одном файле. **Почему проверка слабая:** закон проверяется на двух
   новых мирах `v0_ruin_*`, которых в игре нет, и на шести здоровых — где проигрыша и не
   должно быть. Статус: НАХОДКА 1.
2. **ADR 0209 §Решение 2 — «семейство банкроты» как проигрыш.** Гораздо хуже: порог
   `FAMILY_HUNGER_MONTHS = 3` проверен мутацией и краснеет, но **механика, которая обязана
   довести до порога, в целевом мире не срабатывает ни при каком игровом поведении**
   (НАХОДКИ 1.2, 1.3). **Почему проверка слабая:** тест спрашивает «если голод дойдёт до 3,
   проигрыш ли?» и отвечает «да», не спрашивая «дойдёт ли голод до 3 когда-нибудь?» — а
   второй вопрос и есть игра.
3. **ADR 0213 — окна приёмки `start_stand`.** ADR сам признаёт: «Новых тестов на окно не
   заведено». **Почему проверка слабая:** §Проверка ADR — это `runner` плюс `grep -n "148.7"`
   по документу, то есть проверка не того, что мир производит числа из окна, а того, что
   Scribe не стёр строку. Хеши в окне уже не про этот мир.
4. **ADR 0214 — «рента в баронстве > 0».** Окно `ACCEPTANCE.md` §1a, теста нет. **Почему
   проверка слабая:** это запись о сверке, а не падающая проверка; числа в ней верны только
   пока `economy/` не меняют, а `economy/` переписывают регулярно.
5. **«Шум канала `messenger` делает канал слухом» (`docs/05_information.md:70`).** Формально
   числа сдвинуты, но производные от разбивки точны (НАХОДКА 5), а `distorted=False`
   означает истину в 60 % месяцев (НАХОДКА 6). **Почему проверка слабая:** ни один тест не
   утверждает, что шум канала **остаётся** шумом после вычитания; все проверяют только
   смещение отдельного числа.
6. **ADR 0212 §Решение 6 — «точного числа поселения игрок не знает».** Проверяется на
   `v0_barony_100`, где поселение шире клетки, и потому проходит; на шести мирах из девяти
   глаз **и есть** точная сумма поселения (НАХОДКА 7). **Почему проверка слабая:** тот же
   класс, что и НАХОДКА 2 первого критика (`0208`    §3) — проверка стоит на стенде, где
   оба прочтения совпадают.
7. **Живость `Good.storage` (И-7).** Инвариант И-7 требует «у каждого товара есть `storage`»,
   поле есть у 55 из 55, `test_catalog_rules.py` зелёный — и поле не читается никем
   (НАХОДКА 9). **Почему проверка слабая:** И-7 проверяет **наличие ярлыка**, а не свойство;
   закон доволен ровно тем, что `Good.storage` ничего не делает.
8. **Сторож мёртвых полей как таковой.** AST-сторож стал строже regex-а, но обманывается
   записью вместо чтения и одноимённым полем чужого объекта (НАХОДКА 8), а его собственный
   тест (`test_a_name_that_only_looks_like_a_read_is_not_a_reader`) проверяет **только**
   объявления, строки и вызовы — те три обмана, которые он починил. **Почему проверка слабая:**
   она закрепляет свой же успех и не закрепляет провала.

## Что запрещено следующим агентам

- **Не публиковать в ADR «проигрыш достижим» по двум новым мирам `v0_ruin_*`, не показав
  достижимость в целевом мире.** Это ровно то, чем ADR 0209 выглядит сегодня: два честных
  замера на стендах, которых нет в игре (НАХОДКИ 1.2, 1.3).
- **Не считать `test_barony_100_does_not_lose` доказательством баланса.** Это утверждение об
  отсутствии проигрыша, а не о его достижимости.
- **Не разводить дрейф «на весь отчёт» и «на каждое число», полагая, что это одно и то же.**
  Один бросок убивает шум на всех производных величинах (НАХОДКА 5).
- **Не отдавать игроку флаг «не искажено» из канала с `confidence < 1.0`.** `distorted=False`
  при `confidence 0.5` — это истина под слухом (НАХОДКА 6).
- **Не считать `Good.storage` выполненным И-7 по наличию поля.** 55 ярлыков, 0 читателей
  (НАХОДКА 9).
- **Не добавлять в `ZERO_READ_ALLOWLIST` поле, не проверив его grep-ом руками.** Проверка
  `ctx` в `read_field_names` не сделана, поэтому запись `obj.field = x` читателем считается
  (НАХОДКА 8).
- **Не опираться на числа окон ADR 0213/0214 как на актуальные.** Хеши устарели, теста нет
  (НАХОДКА 4).
- **Не переоткрывать ADR 0209 и ADR 0209-историю правкой на месте.** Любое изменение — новый
  ADR со ссылкой на этот (`AGENTS.md` §8).
- **Не запускать мутации в живом дереве.** ADR 0167:45-48: копия байт **до** правки,
  `diff -q` чист, иначе правка чужой зоны.
