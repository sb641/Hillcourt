# 0085. Исполнение: кандидат миграции только пригоден (Implementer)

Дата: 2026-09-24. Роль: Implementer. Исполнен ADR 0080 в `engine/tile_view.py`,
`engine/tick.py` и `sim/tests/`. Старые ADR не правятся.

## Назначение

Уходящий двор не должен выбирать воду, руину без жилья или режим без dwelling только
потому, что на клетке меньше пяти дворов. Если шесть соседей заняты или непригодны,
двор остаётся на месте.

## Правила

1. `can_settle` сначала проверяет пригодность, затем механический кап.
2. Вода и руина без `dwelling` не являются кандидатами; руина с dwelling допустима.
3. Поселение, dwelling-маркер и urban-маркер означают место; `waste`,
   `reserved_wood` и `foreign` без dwelling не означают.
4. `phase_migrate` по-прежнему выбирает максимум одного соседа и не вводит глобальный
   кап плотности; при отсутствии кандидата ухода нет.

## Проверка

```bash
PYTHONPATH=sim/src python3 -m unittest sim.tests.test_migration_candidate sim.tests.test_communal_access -v
bash sim/run_tests.sh
```

Тесты проверяют воду, руину без dwelling, режим без dwelling и шесть занятых соседей.
Полный сюит: `Ran 642 tests ... OK`; дельта 0.

## Альтернативы

- Считать пригодность только капом отклонено: это возвращает миграцию в воду и руины.
- Разрешить глобальный обход шести соседей отклонено: волна миграции должна быть
  по одному гексу в месяц.

## Последствия

Кандидаты миграции сузились, поэтому часть дворов остаётся голодной честно. Это
изменило путь соли: регрессионный пин `test_communal_access` переведён с 7.33 на
перемеренные 6.0; данные не подгонялись. Окна §1 и инварианты «соль не врёт»,
дельта 0 сохранены.

## Что запрещено следующим агентам

1. Считать пригодность только числом дворов.
2. Выбирать воду или руину без dwelling.
3. Перемещать двор дальше одного гекса за месяц.
4. Вводить глобальный кап плотности.
