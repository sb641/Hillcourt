# 0059. Нативная деревня v1: племя без новой сущности (владелец)

Дата: 2026-09-24. Решение хозяина-человека по видению баронства: «в баронстве уже должны
быть нативные деревни, где живёт местное племя; фронтир, и наша задача в том числе
управлять и в том числе их жизнью обеспечивать». Открывает этап — узкий, без новых сущностей.

## Контекст

- Legal-разведка (цикл 29): простая свободная община выражается существующими сущностями
  (`free_landless` + `Settlement.kind=village` + communal-доступ); коллективный землевый
  титул не выражается (`Right.kind=common` декларативен, группового носителя нет);
  присяга без последствий — ложь, в закон не идёт.
- Systems-стади-гейт (цикл 29): `tribal`/`tribal_village` есть только в виде; `LAND_MARKS`
  не грузятся сценарием (`scenario.py` читает только `fords`/`bridges`/`roads`) — без
  правки загрузчика маркер из YAML не появится.
- Бюджет сложности: этап открывается узко; новый слой — только отдельным ADR.

## Решение

1. **v1 = разметка + данные, право — существующее.** Племенная деревня: `Settlement.kind=village`
   с маркером `tribal` на клетке; дворы — пресет `free_landless`; общая земля — через
   существующий communal-доступ и `Right.kind=grazing`. Новых сущностей и полей мира нет.
2. **Рычаг игрока — существующее право.** Над племенем доступны только уже вшитые
   действия: `grant_tenure` (включая `common`/`grazing`), `add_obligation` (`levy`,
   фиксированный/доля), выдача/снятие доступа к `works_tiles` и пастбищам. Никакого
   принудительного труда и связывания в v1: присяга без последствий — ложь.
3. **Загрузчик.** `scenario.py` учитывает секцию маркеров (`tribal`, `tavern_site`,
   `baron_castle`, статическая `trail`) — это данные вида, не механика.
4. **Знание — И-3.** О племенной деревне игрок узнаёт из существующих каналов
   (`eye_from_hill` в радиусе глаза, `adjacent_daily`, `caravan`); новых каналов нет.
   Текст вести — за Info (формулировки, не новый тип знания).
5. **Отложено (отдельными ADR, позже):** `Community`/коллективный титул, присяга с
   последствиями, вербовка/договор с общиной, институциональное переселение, рынок
   невольников, города 100–200 дворов, уровни домов, таверна-механика, служба 60–90 дней,
   ~10 баронств.

## Альтернативы

- Сразу ввести `Community` как субъект права — отклонено: цена (онтология, действия,
  вести) не влезает в бюджет этапа; v1 покажет, нужна ли власть над общиной.
- Только визуальная деревня без рычага — отклонено: ярлык без закона (ворует
  ощущение управления, но не даёт); v1 даёт право через существующие действия.
- Ничего не делать — отклонено: видение хозяина прямо требует племя на земле.

## Последствия

- Требуется: маркер в сценарии + поддержка секции в загрузчике (Implementer), текст
  вести (Info), форма вида уже есть (World, ADR 0054), sync доков после приёмки (Scribe).
- Канон не должен сдвинуться: нативная деревня появляется в отдельном сценарии/своей
  клетке; окна §1 (two ≥ 14, shire 24–28) сохраняются, дельта 0.
- Критерий честности: игрок может наложить `levy` на племенной двор и снять communal-доступ
  существующими действиями; племенной двор сам уходит при голоде (общий агент двора).

## Что запрещено следующим агентам

1. Вводить `Community`/присягу/рынок невольников без нового ADR владельца.
2. Давать племени трудовую повинность или `tied`-пресет в v1.
3. Расширять `known_tiles` от племени (знание только из `Report`).
4. Менять канон/окна под этот этап.

## Проверка

```bash
bash sim/run_tests.sh
PYTHONPATH=sim/src python3 -m hillcourt.runner --scenario <сценарий_с_племенем>.yml --months 12
```

Критерий: сюит зелёный; маркер грузится из YAML; `levy` и снятие доступа работают
существующими действиями; вести о племени идут существующими каналами; дельта 0.
