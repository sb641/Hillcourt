# 0024. Наполнение тайла и контракт вида

Дата: 2026-09-21. Роль: наполнение тайла (Implementer-зона `sim/src/hillcourt/engine/`).
Субагенты (обязательный ролевой разбор): игрок стратегической карты; житель
одинокого двора; тэн с усадьбой на клетку; путник по иконке пустошь/деревня.

## Контекст

Клетка была бесконечной коммуной: жилых дворов на ней могло стоять сколько
угодно, а вида у клетки не было вовсе — иконку стратегической карты было
не из чего рисовать, кроме ручной краски. Задача: кап жилых дворов (ориентир
5) как Legal-правило с явным отказом сверх капа, и вид `tile_view`
(`form`, `household_count`, `has_seat`, `has_thegn_hall`, `terrain`) как чистая
функция состояния. Не рендерер Godot — снимок, из которого потом рисуют иконку.
Чужое не тронуто: служба тэна (комплекты/явки/`mustered`), реки, скот, yield,
барщина, pathfinder, спрайты. Кап пашни (`plot_batch_cap_per_tile = 4`, G3) живёт
отдельно и не ломается: он про партии жатвы, кап дворов — про место жительства
(`Household.current_tile_id`).

Привязки в коде: двор живёт на клетке через `current_tile_id` (сценарий ставит
его из `settlement.coord`); `Tile` списка дворов не хранит. Seat корня — клетка
поселения `kind == hill_court`. Seat тэна выводится по книге (`manor_of_tile`),
а не по тому, где спит двор держателя. Legacy-переполнение старше капа
(16 дворов ясеня на одной клетке в `v0_shire`) существует и тестами защищено —
его нельзя объявить ошибкой загрузки.

## Решение

Новый модуль `sim/src/hillcourt/engine/tile_view.py` (единственное место вида):

- Кап: `TILE_MAX_HOUSEHOLDS = 5`, эквивалент `tile.max_households`
  (`tile_max_households(world, tile)`; хук под будущее поле `Tile.max_households`
  без смены онтологии сейчас). Счёт — только живые (`left_at is None`).
- Посадка: `settle_household(world, household, tile)` двигает ТОЛЬКО место
  (`current_tile_id` + точки людей); стоки, труд, режимы, права, книги не
  меняются. Сверх капа — `PermissionError` + запись `settle_rejected
  reason=tile_full` в `player_actions` (шестой при капе 5 не садится).
- Каталог форм (7, городов нет): `open_field` (пусто, hill/field/pasture),
  `forest` (пусто, forest), `waste` (пусто, marsh/heath/salt_flat/ruin/water),
  `single_homestead` (1 двор), `village` (2+, включая legacy-переполнение),
  `thegn_estate` (seat тэна), `hall_on_hill` (seat корня).
- Seat тэна: по одному на вложенный манор — первая доменная клетка книги
  (`manor.tile_ids` по порядку гранта), fallback первая клетка. Остальные клетки
  фьефа — угодья (вид по счётчику, не вторая усадьба). После `grant_thegn`
  seat — `thegn_estate`, даже если двор держателя спит на холме и на seat
  ноль жилых дворов.
- Приоритет формы: зал корня > усадьба тэна > счётчик. `hall_on_hill` держится
  поселением `hill_court`, а не книгой (грант холмовой клетки его не снимает).
- Снимок `tile_view(world, tile)` / `TileView.as_dict()` / `dump_tile_views(world)` /
  `format_tile_view` — чистое чтение (материя/труд не меняются, И-1/И-5).
- Интеграция: `phase_migrate` не выбирает полного соседа (некуда — остаётся);
  `resolve_migrations` при гонке (назначение полно к прибытию) возвращает двор на
  исходную клетку с `messenger` о тесноте (`settle_rejected_arrival`), груз цел.
  Загрузка сценария кап не проверяет (legacy живёт). `runner --print-log` печатает
  «Клетки (вид без RimWorld-слоя)» — игрок видит `form` в логе/дампе; знанием по
  И-3 снимок не является (знание — только `Report`).

Пример дампа (`v0_hill_and_salt`, seed сценария):

```text
пусто:        t_00_00 forest forest дворов=0 seat=0 hall=0
пусто:        t_02_00 heath waste дворов=0 seat=0 hall=0
пусто:        t_04_00 pasture open_field дворов=0 seat=0 hall=0
1 двор:       t_00_00 forest single_homestead дворов=1 seat=0 hall=0
4 двора:      t_00_00 forest village дворов=4 seat=0 hall=0
seat тэна:    t_05_02 field thegn_estate дворов=0 seat=0 hall=1
угодье фьефа: t_03_01 field single_homestead дворов=1 seat=0 hall=0
seat корня:   t_01_01 hill hall_on_hill дворов=2 seat=1 hall=0
```

Проверка: `sim/tests/test_tile_view.py` (13 зондов: кап 5 + отказ 6-го с записью,
каталог без города, пустые по terrain, 1 vs 4 → разный form, зал корня, грант →
estate а не хутор, legacy-переполнение → village, дамп с полями, чистота снимка,
тик с капом дельта 0). Полный прогон: `bash sim/run_tests.sh` — 296 OK.

## Альтернативы

- Поле `Tile.max_households` в онтологии + миграция сценариев: отвергнуто —
  смена онтологии ради константы и переписывание `v0_shire` (16 дворов ясеня)
  ломает F1-стресс и канон голода; эквивалент-константа + хук дешевле.
- Все клетки фьефа — `thegn_estate`: отвергнуто по разбору тэна — тогда у тэна
  три усадьбы вместо одной с угодьями; флаг `has_thegn_hall` теряет смысл.
- Seat тэна по `current_tile_id` держателя: отвергнуто — держатель спит на холме,
  клетка фьефа осталась бы хутором вопреки пожалованию; вид берётся по книге.
- Форма в `Report.facts` для игрока (знание по И-3): отложено — не входит в зону;
  игрок видит `form` в отладочном логе/дампе runner, знание остаётся за Info.
- Кап в `grant_tenement` (право пахать): отвергнуто — это кап пашни G3, уже
  делится; смешение дало бы двойной счёт и сломало соль A1.

## Последствия

- Стратег видит иконку из `form` без RimWorld-слоя; решения (`grant_thegn`,
  `send_party`) читают `household_count`/`has_seat`/`has_thegn_hall`.
- Миграция не уплотняет полные клетки; гонка прибытий возвращается к исходной.
- Legacy-переполнение называется `village` и новых прав не даёт.
- `form` не входит в `state_hash` и экономику: урожай, служба, труд те же.

## Что запрещено следующим агентам

- Давать `form` экономический бонус (урожай, труд, служба, `mustered`): вид —
  чистый рендер, иначе скрытый tech-tree и нарушение И-5.
- Тихо сажать сверх капа или «удваивать выход» вторым двором: только явный
  `settle_rejected`; кап пашни G3 не переносить на кап жителей и наоборот.
- Заводить городской тайл/рынок/лор имён без сущности в `docs/03_ontology.md`.
- Класть спрайты/Godot-импорты в `sim/`; считать ренту в рендере.
- Проверять кап в загрузчике сценария задним числом (сломает `v0_shire`/F1).
- Писать формы в `design/catalogs/` (чужая зона Economist/Legal) — каталог форм
  живёт в `engine/tile_view.py:FORMS`.
